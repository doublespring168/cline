> 分析基线：提交 `fae0c4674`。版本以各级 `package.json` 为准；仓库不同子项目存在独立版本，不能假定所有前端都使用同一 React/TypeScript 版本。

## 2. 语言、运行时与工作区

### 2.1 TypeScript

TypeScript 是绝对主语言。根工作区声明 `typescript ^5.9.3`，SDK 包以 ESM 发布；VS Code 工程有独立依赖和 tsconfig。它主要承担：

- `AgentRuntimeEvent`、`CoreSessionEvent` 等判别联合；
- `RuntimeHost`、`SessionStore`、`AgentModel` 等端口；
- Provider、插件、MCP 和工具的泛型契约；
- CLI、React UI 与协议客户端；
- 测试中的类型级边界验证。

关键位置：`sdk/packages/*/src/`、`apps/cli/src/`、`apps/cline-hub/src/`、`apps/vscode/src/`。

### 2.2 Bun

根 `package.json` 固定 `bun@1.3.13`。Bun 同时扮演：

- workspace 包管理器；
- TypeScript 脚本运行器；
- SDK/CLI 构建器；
- `apps/cline-hub` 的 HTTP/WebSocket 服务端；
- SQLite 运行时之一（`bun:sqlite`）；
- 测试和发布脚本的编排器。

Hub Dashboard 的 `apps/cline-hub/src/server.ts` 直接使用 `Bun.serve`，说明 Bun 在该应用中不只是开发工具，而是生产运行时。

### 2.3 Node.js

根工程要求 Node.js `>=22`。SDK 的 SQLite 抽象会在非 Bun 环境加载 `node:sqlite`，Hub/CLI 也使用大量 Node 标准库。因此对外发布的 SDK 不是 Bun-only。

`sdk/packages/shared/src/db/sqlite-db.ts` 对 `bun:sqlite` 和 `node:sqlite` 做统一封装，属于明确的跨运行时适配。

### 2.4 Rust/Tauri

`apps/examples/desktop-app` 和 `apps/examples/menubar` 使用 Tauri 2，`src-tauri/src/main.rs` 提供原生桌面外壳，业务 Sidecar 仍由 Bun/TypeScript 运行。它们是 SDK 的宿主示例，不是主 CLI 的依赖。

## 3. Agent 与模型技术

### 3.1 自研 AgentRuntime

`@cline/agents` 没有依赖一个通用 Agent 框架，而是在 `agent-runtime.ts` 中实现：

- 多轮迭代；
- 流式文本、推理和 Tool Call 组装；
- 串行/并行工具执行；
- Hook；
- 中止、重试、最大迭代和完成策略；
- Token/费用累计；
- 结构化事件发布。

这使 Cline 可精确控制编码 Agent 的工具语义、审批、上下文和兼容事件。

### 3.2 Vercel AI SDK 6

`@cline/llms` 依赖 `ai ^6.0.144` 及 `@ai-sdk/*` Provider。主要功能是：

- 将不同厂商 SDK 统一为流式生成接口；
- 标准化 Tool Call、usage、finish reason 和消息结构；
- 支持 OpenAI-compatible 等通用协议；
- 为 Gateway Provider 适配器提供基础能力。

模型请求最终由 `sdk/packages/llms/src/providers/gateway.ts` 选择 Provider 和模型，并返回 `AsyncIterable<AgentModelEvent>` 给 Agent。

### 3.3 Provider SDK 与协议

新 `@cline/llms` 的主要 Provider 家族包括：

- OpenAI、OpenAI-compatible、OpenAI Codex/CLI；
- Anthropic、Claude Code；
- Google Gemini、Vertex AI；
- AWS Bedrock；
- Mistral；
- OpenRouter、Cline、Ollama、LM Studio；
- Dify、SAP AI Core、OpenCode 等。

其实现位于 `sdk/packages/llms/src/providers/`，内置声明在 `builtins.ts`，模型目录在 `catalog/`，协议编码规则在 `providers/routing/`。

`apps/vscode/src/core/api/providers/` 还保留更多历史 Provider 实现，如 Cerebras、Groq、Requesty、LiteLLM、Qwen、DeepSeek、Moonshot 等。改 Provider 时必须先判断目标是新 SDK、旧 VS Code，还是两者都要覆盖。

### 3.4 Provider 路由规则

该项目不只是“按 providerId 调 SDK”。其路由链是：

```text
请求意图 + 模型事实 + Provider metadata
    → 命名的 option rule
    → 厂商 wire format
```

对应源码：

- 模型事实：`llms/src/providers/model-facts.ts`；
- Provider metadata：`llms/src/providers/builtins.ts`；
- 编码规则：`llms/src/providers/routing/`；
- Registry：`llms/src/providers/registry.ts`。

这用于处理推理强度、Prompt Cache、路由别名、最大输出 Token 等供应商差异。

## 4. Schema、配置和序列化

### 4.1 Zod

SDK 主要使用 Zod 4。用途包括：

- 工具输入 Schema 与运行时校验；
- JSON Schema 生成，传给模型；
- 插件 Manifest、Cron Spec、团队状态、远程配置；
- CLI 参数和协议消息；
- 对不可信文件/网络输入做边界校验。

共享转换工具位于 `sdk/packages/shared/src/parse/zod.ts`，工具 Schema 位于 `core/src/extensions/tools/schemas.ts`。

桌面示例仍有 Zod 3 依赖，说明示例前端版本独立。

### 4.2 YAML + Markdown Frontmatter

项目把 Markdown 用作可执行配置载体：

- Cron/事件自动化 Spec；
- Rules、Skills、Workflows；
- Agent 配置和插件说明；
- 自动化运行报告。

`yaml ^2.8.2` 负责 Frontmatter 数据；正文承载给模型的自然语言说明。其优势是可读、可审查、可由 Git 管理。

### 4.3 Jiti 与动态模块

`@cline/core` 使用 `jiti` 及动态 import 加载 TypeScript/JavaScript 插件。`extensions/plugin/plugin-module-import.ts`、`plugin-loader.ts` 和 `plugin-sandbox.ts` 负责模块解析、能力校验和隔离。

## 5. 工具与扩展协议

### 5.1 内置工具体系

新 Core 的主要内置工具包括：

| 工具 | 主要功能 | 位置 |
| --- | --- | --- |
| `read_files` | 批量读取文本/图片和行区间 | `extensions/tools/definitions.ts`、`executors/file-read.ts` |
| `search_codebase` | 正则搜索代码 | `executors/search.ts` |
| `run_commands` | 运行命令、流式输出、超时控制 | `executors/bash.ts` |
| `fetch_web_content` | 获取网页内容 | `executors/web-fetch.ts` |
| `apply_patch` | 解析并应用 Patch | `executors/apply-patch.ts` |
| `editor` | 结构化文件编辑 | `executors/editor.ts` |
| `skills` | 按需加载技能说明 | `extensions/config/` |
| `ask_question` | 请求宿主/用户输入 | `definitions.ts` |
| `submit_and_exit` | 显式完成运行 | `definitions.ts` |

每个工具由 Schema、定义、执行器、策略和审批共同组成，而不是一个裸函数。

### 5.2 MCP

依赖 `@modelcontextprotocol/sdk ^1.29.0`，支持：

- stdio、SSE、Streamable HTTP 传输；
- MCP 工具发现和调用；
- OAuth；
- 配置加载与连接状态；
- 插件注册 MCP Server；
- MCP Tool 与内置 Tool 合并。

新实现位于 `sdk/packages/core/src/extensions/mcp/`；旧 VS Code 实现位于 `apps/vscode/src/services/mcp/`。

### 5.3 ACP

CLI 依赖 `@agentclientprotocol/sdk ^0.16.1`。`apps/cli/src/acp/` 将 Cline 暴露为 Agent Client Protocol Agent，使其他兼容编辑器/客户端可以创建会话、发送 Prompt、切换模型/模式并接收更新。

### 5.4 插件与 Hook

项目自有插件协议提供：

- 工具；
- 生命周期 Hook；
- 命令；
- 规则、技能等指令；
- Provider；
- 自动化事件类型。

Hook 可拦截 `beforeRun/afterRun/beforeModel/afterModel/beforeTool/afterTool/onEvent`。这类技术用于审计、策略、输入改写、指标和领域工具扩展。

## 6. 通信技术

### 6.1 WebSocket 与 Hub RPC

`@cline/core` 使用 `ws ^8.20.0` 提供 Node WebSocket 服务。Hub 协议采用带版本的 JSON Envelope：

```text
command → reply
event   → subscriber
capability request → client-owned executor/approval
```

协议契约在 `sdk/packages/shared/src/hub.ts`、`rpc/`，服务端在 `core/src/hub/server/`，客户端在 `core/src/hub/client/`。

### 6.2 Bun HTTP/WebSocket

`apps/cline-hub` 使用 `Bun.serve` 同时提供：

- SPA 静态资源；
- `/health`、`/version`、Marketplace 等 HTTP 接口；
- `/browser` WebSocket；
- Room Secret 鉴权；
- 浏览器协议到 Core/Hub 的转换。

### 6.3 Protocol Buffers 与 gRPC

正式 VS Code 扩展在 `apps/vscode/proto/` 定义服务，使用 `@grpc/grpc-js`、`nice-grpc`、`@bufbuild/protobuf`。其用途包括：

- Extension Host 与 Webview 的 RPC；
- 独立模式/Host Bridge；
- 文件、窗口、终端、模型、账户、状态、MCP 等服务；
- 流式订阅 UI 状态。

生成脚本是 `apps/vscode/scripts/build-proto.mjs`，生成代码进入 `src/generated` 和 Webview gRPC 客户端。

## 7. 数据与存储技术

### 7.1 SQLite

新 Core 使用三个主要数据库域：

- `sessions.db`：会话元数据；
- `teams.db`：团队快照、成员和运行；
- `cron.db`：Spec、Run、事件日志和队列。

底层通过 `SqliteDb` 端口统一 `bun:sqlite` 与 `node:sqlite`，并实现 `SQLITE_BUSY/LOCKED` 重试。相关源码：

- `shared/src/db/sqlite-db.ts`；
- `core/src/services/storage/sqlite-session-store.ts`；
- `core/src/services/storage/sqlite-team-store.ts`；
- `core/src/cron/store/sqlite-cron-store.ts`。

旧 VS Code 依赖 `better-sqlite3`，主要用于其独立存储/运行场景。

### 7.2 文件系统存储

文件仍是不可替代的一等存储：

- 消息、Manifest、Checkpoint 和 Artifact；
- `~/.cline` 与工作区 `.cline/` 配置；
- Rules、Skills、Workflows、Hooks、Plugins；
- Hub discovery 和锁；
- Cron 报告；
- Provider 设置和迁移数据。

Core 在 SQLite 不可用时会回退 `FileSessionService`，体现存储适配器模式。

### 7.3 Git 与 Checkpoint

新 Core 依赖 `simple-git`；CLI 和 VS Code 还直接使用 Git/工作树能力。VS Code 的检查点实现集中于 `apps/vscode/src/integrations/checkpoints/`，支持任务级快照、差异和恢复；CLI/Core 提供 Checkpoint 恢复及 Session Fork 能力。

## 11. 可观测性与日志

### 11.1 OpenTelemetry

Core 集成 Trace、Metric、Log 的 OTLP HTTP Exporter，配置由环境变量和远程配置归一化。主要实现：

- `core/src/services/telemetry/OpenTelemetryProvider.ts`；
- `OpenTelemetryAdapter.ts`；
- `shared/src/remote-config/telemetry.ts`。

### 11.2 PostHog

CLI 使用 `posthog-node`，VS Code 同时使用 Node 和 Web `posthog-js`，负责产品事件、Feature Flag 和激活分析。

### 11.3 Langfuse

`@cline/llms` 使用 `@langfuse/otel`，在模型层提供 LLM Trace 关联。实现位于 `llms/src/services/langfuse-telemetry.ts`。

### 11.4 Pino 与 BasicLogger

CLI 用 Pino 写结构化日志；跨包只依赖 `BasicLogger` 小接口。这样 Core 不直接依赖某个日志实现，VS Code 可映射到 OutputChannel，服务端可映射到 Pino。

## 14. 安全相关技术

| 风险 | 实现措施 |
| --- | --- |
| 危险工具调用 | Tool Policy、自动批准开关、宿主审批回调 |
| 路径越界 | 工作区路径规范化、工具执行器校验 |
| 插件执行 | Manifest 能力校验、Plugin Sandbox、子进程隔离 |

| 密钥 | Provider Settings、环境变量、敏感字段标注 |
| 命令挂死 | AbortSignal、超时、输出上限、子进程清理 |

## 15. 技术选型的整体逻辑

这些技术的组合服务于三个核心目标：

1. **跨宿主**：TypeScript 契约、端口适配、WebSocket/gRPC 让同一能力可进入 CLI、IDE、Web 和 SDK。
2. **可扩展**：Zod、MCP、插件、Hook 和文件配置使功能可以在不修改 Agent 循环的情况下扩展。
3. **可持续运行**：SQLite、Hub、队列、OpenTelemetry、审批和沙箱让 Agent 能从交互工具扩展到后台服务与自动化。

因此理解技术栈时，不应把它看成一张依赖清单；其主线是“统一模型流 + 结构化工具 + 有状态编排 + 多宿主适配”。
