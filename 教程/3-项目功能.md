## 2. 智能体对话与任务执行

### 2.1 多轮对话

用户可以提交自然语言任务，模型按“思考/输出 → 调工具 → 获取结果 → 继续”的方式多轮执行，直到显式完成、失败、中止或达到迭代限制。

| 子功能 | 源码 |
| --- | --- |
| 消息标准化与恢复 | `sdk/packages/agents/src/agent-runtime.ts` 的 `normalizeInput()`、`restore()` |
| 迭代循环 | 同文件 `execute()` |
| 模型流消费 | 同文件 `generateAssistantMessage()` |
| Tool Call 拼装 | 同文件 `tool-call-delta` 分支 |
| 工具结果回填 | 同文件 `executeToolCalls()` |
| 完成/失败/中止 | `finishRun()`、`AgentRuntimeAbortError` |
| 会话级 API | `sdk/packages/core/src/ClineCore.ts` |

### 2.2 流式文本和推理

模型的文本和 reasoning 以 delta 事件实时发送，最终再形成完整消息；UI 可同时显示回答、推理块、工具状态和用量。

- 原始事件：`sdk/packages/shared/src/agent.ts`；
- Agent 事件发射：`sdk/packages/agents/src/agent-runtime.ts`；
- 兼容转换：`sdk/packages/core/src/runtime/orchestration/runtime-event-adapter.ts`；
- 会话投影：`sdk/packages/core/src/services/agent-events.ts`；
- CLI 展示：`apps/cli/src/tui/hooks/use-agent-events.ts`；
- Hub 展示：`apps/cline-hub/src/server/agent-events.ts`、`src/webview/src/Chat.tsx`；
- VS Code 展示：`apps/vscode/webview-ui/src/components/chat/`。

### 2.3 Plan、Act 与 YOLO

| 模式 | 行为 | 主要位置 |
| --- | --- | --- |
| Plan | 侧重探索和方案，限制修改类工具 | `core/src/extensions/tools/presets.ts`、`model-tool-routing.ts` |
| Act | 可读、搜、执行、编辑，但危险工具按策略审批 | 同上及 `runtime/tools/tool-approval.ts` |
| YOLO | 更自动化，默认减少交互并要求完成工具 | CLI `--yolo`，Core Tool Preset/Policy |

CLI 在 `apps/cli/src/commands/program.ts` 暴露 `--plan`、`--yolo` 等参数；VS Code 旧实现对应 `apps/vscode/src/core/task/tools/handlers/PlanModeRespondHandler.ts`、同目录的 `ActModeRespondHandler.ts`。

### 2.4 运行控制

用户和宿主可以：

- 中止当前工具/Turn；
- 停止整个会话；
- 继续已有会话；
- 在运行中发送 steer Prompt 或排队 Prompt；
- 切换活动会话模型；
- 查询根 Agent 和聚合团队用量。

主要源码：

- `ClineCore.abort/stop/send/getAccumulatedUsage`：`core/src/ClineCore.ts`；
- 待处理 Prompt：`core/src/runtime/turn-queue/pending-prompt-service.ts`；
- 会话模型服务：`core/src/cline-core/runtime-services.ts`；
- CLI 队列 UI：`apps/cli/src/tui/components/queued-prompts.tsx`。

## 4. 模型与 Provider 功能

### 4.1 统一模型网关

用户可以配置 Provider、模型、API Key、Base URL、Header、推理强度、Thinking 和最大 Token。Gateway 负责：

1. 查找 Provider Manifest；
2. 合并默认与用户配置；
3. 解析默认/指定模型；
4. 按模型上下文窗口限制输出；
5. 创建 Provider 并转换流。

主要源码：

- `sdk/packages/llms/src/providers/gateway.ts`；
- `providers/registry.ts`；
- `providers/builtins.ts`；
- `catalog/`；
- `providers/routing/`。

### 4.2 Provider 管理

Core 提供 Provider 设置发现、读写、旧配置迁移、本地模型发现和可用性校验：

- `core/src/services/storage/provider-settings-manager.ts`；
- `core/src/services/providers/local-provider-service.ts`；
- `core/src/services/providers/provider-config-fields.ts`；
- `core/src/services/llms/`。

CLI 的 `auth`、`config` 和模型选择 UI 在 `apps/cli/src/commands/auth.ts`、`config.ts`、`tui/components/model-selector/`。Hub 的模型/Provider 管理在 `apps/cline-hub/src/server/providers.ts` 与 Webview Settings。VS Code 的历史 Provider UI 位于 `apps/vscode/webview-ui/src/components/settings/providers/`。

### 4.3 OAuth 和账户

- Core OAuth 本地回调：`core/src/auth/server.ts`；
- CLI Provider 登录：`apps/cli/src/commands/auth.ts`、`utils/provider-auth.ts`；

- MCP Hub；

- 远程配置；

`apps/vscode/src/core/task/` 的 `Task` 负责：

### 17.4 终端与命令

### 17.6 Standalone/Host Bridge

`apps/vscode/src/standalone/` 可把 Cline Core 作为独立进程运行；`hosts/vscode/hostbridge/` 把文件、Diff、窗口、剪贴板、终端和工作区能力通过 Proto/gRPC 暴露给该进程。

## 18. SDK 对外开发功能

`@cline/sdk` 重新导出 `@cline/core`，第三方可：

- 直接创建轻量 `Agent`；
- 创建 `ClineCore` 和有状态会话；
- 注册自定义 Tool；
- 配置模型/Provider；
- 注入 Logger、Telemetry、能力和审批；
- 编写 Plugin 和 Hook；
- 启用 MCP；
- 启用 Sub-agent/Team；
- 运行自动化；
- 连接 Hub 或远程 Hub。

入口：`sdk/packages/sdk/src/index.ts`、`sdk/packages/core/src/index.ts`。

## 20. 本仓库之外的产品边界

根 README 还提到 JetBrains 和 Kanban，但：

- JetBrains 插件源码未在此仓库开源；
- Kanban 主实现位于独立 `cline/kanban` 仓库，本仓库只有 CLI 启动/迁移相关代码。

因此改造当前仓库不能假定可以直接修改这两项产品的完整实现。

## 21. 功能定位速查

```text
模型问题            → sdk/packages/llms
Agent 循环/流/工具编排 → sdk/packages/agents
会话/工具/插件/MCP    → sdk/packages/core
CLI 命令和 TUI       → apps/cli
浏览器 Hub 面板      → apps/cline-hub
正式 VS Code 功能    → apps/vscode
第三方集成示例       → apps/examples、sdk/examples
模型真实能力评测      → evals
```

如果同一概念在 `sdk/packages/core` 与 `apps/vscode/src/core` 同时出现，前者通常是新跨宿主实现，后者通常是正式 VS Code 当前仍在使用的历史实现，改动前必须确认实际入口。
