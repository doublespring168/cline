# 将 Cline 改造成独立 VS Code 插件并本地安装

> 本文只描述改造和安装步骤，不会直接修改当前项目身份。  
> 示例新插件：显示名 `My Agent`，内部名 `my-agent`，发布者 `mycompany`。请替换成自己的值。

## 1. 先区分两种“独立”

“换一个插件名”可能代表两种完全不同的目标。

### 1.1 A 级：独立 VS Code 扩展身份

目标：

- 插件名称、图标和命令独立；
- 能与官方 Cline 同时安装；
- 生成自己的 VSIX；
- 仍可以使用原 Cline 后端、账号、MCP Marketplace 和数据格式。

需要修改：Extension ID、View ID、Command ID、图标、文案和少量硬编码。

### 1.2 B 级：完全独立产品

除 A 级外，还要求：

- 使用自己的数据目录；
- 使用自己的 API/Auth/Account/MCP 后端；
- 不向 Cline PostHog/OTEL 发送遥测；
- 使用自己的 OAuth Callback 和网页域名；
- 使用自己的 Remote Config、Feature Flags、Marketplace；
- 可选择重新命名 `.clineignore`、`.clinerules`、Skills 等工作区约定。

这不是简单重命名，而是产品后端和数据边界迁移。

### 1.3 推荐顺序

先完成 A 级并安装验证，再做 B 级。一次性全量替换 `Cline` 字符串风险很高，因为 `cline` 同时是：

- 品牌；
- Extension Command 前缀；
- Proto Package 名；
- 类名/类型名；
- 文件格式和目录约定；
- 后端服务名；
- 遥测事件名。

其中只有一部分必须为本地独立安装而修改。

## 2. 定义命名清单

先固定以下值：

| 含义 | 原值 | 示例新值 | 约束 |
| --- | --- | --- | --- |
| 显示名 | `Cline` | `My Agent` | 用户可见，可含空格 |
| Extension Name | `claude-dev` | `my-agent` | 小写，建议字母/数字/连字符 |
| Publisher | `saoudrizwan` | `mycompany` | 决定 Extension ID |
| Extension ID | `saoudrizwan.claude-dev` | `mycompany.my-agent` | 必须全局唯一 |
| Command Prefix | `cline` | `my-agent` | 必须与 Registry/Package 一致 |
| View Container ID | `claude-dev-ActivityBar` | `my-agent-ActivityBar` | 当前 VS Code Profile 内唯一 |
| Sidebar View ID | `claude-dev.SidebarProvider` | `my-agent.SidebarProvider` | 与代码 Registry 一致 |
| Comment Controller ID | `cline-ai-review` | `my-agent-ai-review` | Comments API 内唯一 |
| 数据目录 | `~/.cline` | `~/.my-agent` | 完全独立时必须修改 |
| 环境变量前缀 | `CLINE_` | `MY_AGENT_` | 完全独立时建议修改 |

不要在改到一半时更换 `my-agent` 的写法。Command、View 和代码生成外的硬编码必须完全一致。

## 3. 建立改造分支和基线

```bash
git switch -c fork/my-agent
git status --short
nvm use 22
npm run install:all
npm run protos
npm run check-types
npm run test:unit
npm run test:webview
```

保存一份未改名前的 VSIX 或 Git Tag，便于对照：

```bash
git tag before-my-agent-rebrand
```

如果工作树已有其他人的改动，不要通过 reset/checkout 清除；只修改与独立插件有关的文件。

## 4. 修改 `package.json` 插件身份

## 4.1 顶层元数据

至少修改：

```json
{
  "name": "my-agent",
  "displayName": "My Agent",
  "description": "Your own AI coding agent for VS Code.",
  "version": "0.1.0",
  "publisher": "mycompany",
  "author": {
    "name": "My Company"
  },
  "icon": "assets/icons/icon.png",
  "repository": {
    "type": "git",
    "url": "https://github.com/mycompany/my-agent"
  },
  "homepage": "https://example.com/my-agent"
}
```

同时更新 categories、keywords、bugs、sponsor 等存在的品牌信息。

`name + publisher` 决定安装 ID：

```text
mycompany.my-agent
```

只修改 `displayName` 不会得到独立插件身份。

## 4.2 Activity Bar 和 Sidebar ID

原配置：

```text
claude-dev-ActivityBar
claude-dev.SidebarProvider
```

改为：

```text
my-agent-ActivityBar
my-agent.SidebarProvider
```

需要同步修改 `package.json` 中：

- `contributes.viewsContainers.activitybar[].id`；
- `contributes.views` 的对象 key；
- 该 View 的 `id`；
- 与 View ID 相关的 menu/when 条件（如果有）。

代码中的 Sidebar ID 来自：

```text
src/registry.ts
  ClineViewIds.Sidebar = name + ".SidebarProvider"
```

把 `name` 改为 `my-agent` 后，代码会自动期望 `my-agent.SidebarProvider`，所以 Package 中必须同步。

## 4.3 Command ID

当前 `src/registry.ts` 有特殊逻辑：

```ts
const prefix = name === "claude-dev" ? "cline" : name
```

改名后，Registry 会自动生成：

```text
my-agent.plusButtonClicked
my-agent.mcpButtonClicked
my-agent.addToChat
...
```

因此必须把 `package.json` 所有 `cline.*` 命令和引用改为 `my-agent.*`，包括：

- `contributes.commands`；
- `keybindings`；
- `menus`；
- `view/title`；
- Editor Context Menu；
- SCM、Notebook 和 Comments Menu；
- `when`/`enablement` 中关联的 Context Key。

建议先列出全部出现位置：

```bash
rg -n 'cline\.|claude-dev|cline-ai-review' package.json src scripts
```

不要只修改 Commands 声明。如果 Menu 仍引用旧 ID，命令虽然注册成功，但按钮不会出现或点击无效。

## 5. 修复代码中的身份硬编码

## 5.1 OAuth/IDE Redirect URI

`src/hosts/vscode/hostbridge/env/getIdeRedirectUri.ts` 当前硬编码：

```text
vscode://saoudrizwan.claude-dev
```

应改为从 `ExtensionRegistryInfo.id` 动态生成，例如逻辑上使用：

```text
${vscode.env.uriScheme}://${ExtensionRegistryInfo.id}
```

否则登录成功页可能重新打开官方 Cline，而不是自己的插件。

`extension.ts` 中 `setupHostProvider().getCallbackUrl()` 已使用 `context.extension.id`，这部分是动态的，应保留这种写法。

## 5.2 Review Comment Controller

`src/hosts/vscode/review/VscodeCommentReviewController.ts` 当前硬编码：

```text
cline-ai-review
cline.reviewComment.reply
cline.reviewComment.addToChat
Cline AI Review
```

应分别改为自己的 Controller ID、Command Prefix 和显示名。`package.json` 中 Comments Menu 的：

```text
commentController == cline-ai-review
```

也必须同步。

更稳妥的改造是把 Review Commands 也加入 `ExtensionRegistryInfo.commands`，避免继续维护散落字符串。

## 5.3 Context Keys

当前硬编码 Context Keys 包括：

```text
cline.isDevMode
cline.isGeneratingCommit
```

主要位置：

- `src/extension.ts`
- `src/hosts/vscode/commit-message-generator.ts`
- `package.json` 的 `when` 条件

改为：

```text
my-agent.isDevMode
my-agent.isGeneratingCommit
```

Context Key 不是 Command，但同样需要在写入方和读取方完全一致。

## 5.4 Dev Commands

`src/dev/commands/tasks.ts` 中：

```text
cline.dev.createTestTasks
cline.dev.expireMcpOAuthTokens
```

是硬编码，应与 `package.json` 同步改名，或纳入 Registry。

## 5.5 Extension Development Script

`scripts/run-extension-host.sh` 当前会禁用：

```text
saoudrizwan.claude-dev
saoudrizwan.cline-nightly
```

可以保留为“避免官方 Cline 与开发版冲突”，也可以补充禁用已安装的 `mycompany.my-agent`，防止开发宿主同时加载已安装版本。

## 5.6 Export API 文档

`src/exports/README.md` 示例仍使用：

```text
saoudrizwan.claude-dev
```

如果保留对外 Extension API，应更新 ID、类型名和示例。若不提供第三方调用，可移除或明确标记内部 API。

## 6. 替换用户可见品牌

需要检查：

```bash
rg -n 'Cline|cline\.bot|saoudrizwan|cline-bot' \
  package.json README.marketplace.md walkthrough assets src webview-ui/src scripts
```

重点区域：

| 区域 | 修改内容 |
| --- | --- |
| `package.json` | 标题、分类、命令标题、Walkthrough、Configuration Title |
| `README.marketplace.md` | Marketplace/插件详情 |
| `walkthrough/*.md` | 首次安装引导 |
| `assets/icons` | PNG、SVG、字体 Icon、机器人图片 |
| `webview-ui/src/assets` | Logo、Compact Icon、社交图标 |
| `components/welcome/onboarding/about` | Welcome、登录、About 文案 |
| Settings Links | Docs、Privacy、Dashboard、Support |
| Notifications/Errors | 用户可见错误和更新提示 |
| `src/registry.ts` | 注释和类型名可后续清理 |

### 6.1 不要盲目全局替换

下列内容第一阶段可以保留：

- TypeScript 类名 `ClineMessage`、`ClineDefaultTool`；
- Proto Package `cline.*`；
- 内部 RPC Service Name；
- 数据兼容所需的字段名；
- License 和原作者版权声明。

盲目把全部 `cline` 替换成 `my-agent` 会破坏生成代码、协议包名、外部 SDK 引用和历史数据兼容。

## 7. 更换图标和资源

至少替换：

- `assets/icons/icon.png`
- `assets/icons/icon.svg`
- `assets/icons/robot_panel_dark.png`
- `assets/icons/robot_panel_light.png`
- Webview Logo Components

如果不再使用 `cline-bot.woff` 自定义字体图标，应同时修改：

- `package.json -> contributes.icons`；
- 相关 Command Icon `$(cline-icon)`；
- `.vscodeignore` 的资源包含规则。

VS Code Marketplace 图标建议使用清晰的 128×128 或更高分辨率 PNG，并检查深色/浅色主题。

## 8. 隔离本地数据

如果希望官方 Cline 与 My Agent 同时安装且互不读取设置，仅改 Extension ID 不够。当前共享存储直接使用：

```text
~/.cline/data
~/.cline/endpoints.json
~/.cline/skills
~/Documents/Cline/Agents
.clineignore
.clinerules
```

### 8.1 必须隔离的数据目录

修改 `src/shared/storage/storage-context.ts`：

```text
默认 ~/.cline -> ~/.my-agent
CLINE_DIR -> MY_AGENT_DIR
```

修改 `src/config.ts`：

```text
~/.cline/endpoints.json -> ~/.my-agent/endpoints.json
```

修改 `src/standalone/vscode-context.ts` 和 Standalone Help：

```text
CLINE_DIR -> MY_AGENT_DIR
~/.cline -> ~/.my-agent
```

同时搜索：

```bash
rg -n '~/.cline|"\.cline"|CLINE_DIR|CLINE_ENVIRONMENT' src scripts standalone
```

### 8.2 Distinct ID 和 State Keys

当前有 `cline.generatedMachineId` 等 Key。如果共用数据目录会产生身份和遥测串用。完全独立时应定义自己的 Key，并提供一次迁移策略，而不是直接覆盖旧值。

### 8.3 Rules/Ignore 是否改名

这是产品兼容性选择：

方案一，继续兼容：

```text
.clineignore
.clinerules
```

优点：用户现有项目规则立即可用。缺点：两个插件共享规则语义。

方案二，完全独立：

```text
.myagentignore
.myagentrules
```

需要修改：

- Ignore Controller；
- Rules Discovery；
- Prompt 文案；
- File RPC；
- UI；
- Migration；
- 测试 Fixtures；
- 文档。

推荐第一阶段保留兼容，数据目录先隔离；等产品规则格式稳定后再迁移工作区文件名。

### 8.4 Skills 和 Agents

完全独立时还应修改：

- 全局 Skills 目录；
- `~/Documents/Cline/Agents`；
- Workflow/Hook 默认目录；
- Remote Skills 的来源和开关 Key。

## 9. 切断 Cline 网络服务依赖

如果只是本地换名并仍使用 Cline 服务，可以暂时保留本节内容；如果目标是自己的产品，本节必须完成。

## 9.1 Endpoint

`src/config.ts` 当前内置：

- `https://app.cline.bot`
- `https://api.cline.bot`
- Cline Staging/Local/MCP Endpoint

可选方案：

1. 改成自己的固定 Endpoint；
2. 只支持自托管 `endpoints.json`；
3. 删除 Account Provider，仅保留用户直接填写 API Key 的第三方模型。

最小自托管配置结构是：

```json
{
  "appBaseUrl": "https://app.example.com",
  "apiBaseUrl": "https://api.example.com",
  "mcpBaseUrl": "https://api.example.com/v1/mcp"
}
```

但你的服务必须实现源码期待的认证、用户、组织、模型、Remote Config、Marketplace 等 API；只改 URL 不会自动得到兼容后端。

## 9.2 Auth 和 Account

需要决定：

- 是否保留登录；
- 登录使用什么 Identity Provider；
- Token 前缀和刷新协议；
- 用户、组织、额度和订阅 API；
- OAuth Success Page 如何重定向到 `mycompany.my-agent`；
- Cline Pass/Cline Provider 是否删除或替换。

相关模块：

- `services/auth`
- `services/account`
- `core/controller/account`
- `core/controller/ocaAccount`
- `components/account`
- `components/onboarding`
- `ClineAuthContext.tsx`

如果自己的产品不需要账号系统，最简单的路线是：

- 默认显示 Settings 而不是 Login Onboarding；
- 移除 `cline`/`cline-pass` Provider；
- 只保留用户自带 API Key 的模型 Provider；
- Auth/Account RPC 返回明确的未启用状态；
- 删除 Credits、Organization、Subscription UI。

## 9.3 MCP Marketplace

`McpHub` 本地连接能力可继续保留，但 Marketplace、Remote MCP Servers 和 OAuth Client Registration 可能依赖 Cline API。完全独立时应：

- 换自己的 Marketplace API；或
- 隐藏 Marketplace Tab，只保留手动添加 Server；
- 重新定义 OAuth Redirect Client；
- 移除 Cline Remote Config Allowlist 依赖。

## 9.4 Cline Provider

`src/core/api/providers/cline.ts` 是 Cline 托管模型服务客户端。没有兼容后端时：

- 不要把它设为默认 Provider；
- 从 Provider Selector 和 Onboarding 中隐藏；
- 调整 Default State；
- 可保留源码以便后续实现，或删除并修复 Factory/Types/Proto/UI。

## 10. 遥测、错误和隐私

本地独立插件不应在用户不知情时继续使用原项目的遥测身份。

### 10.1 最安全的初始方案：全部 No-op

让：

- `TelemetryProviderFactory` 返回 No-op；
- `ErrorProviderFactory` 返回 No-op；
- `FeatureFlagsProviderFactory` 返回 No-op 或本地配置；
- Webview 不初始化原 PostHog；
- 移除构建环境中的 Cline PostHog Key。

项目 Self-hosted 模式已经包含 No-op 分支，可以优先复用这个路径。

### 10.2 使用自己的可观测性

如果需要遥测：

- 使用自己的 PostHog Project Key/Host；或
- 配置自己的 OpenTelemetry Collector；
- 修改 Event Namespace 和 User Agent；
- 更新隐私政策和 UI 开关；
- 确保 Secret、文件内容和 Prompt 不被误采集；
- 区分产品必需指标和用户可选遥测。

### 10.3 CSP

`WebviewProvider.ts` 的 CSP 目前允许连接 `*.posthog.com` 和 `*.cline.bot`。完全独立时应改成自己的最小域名列表，并删除不再需要的来源。

## 11. User-Agent、Headers 与链接

需要检查：

- `services/EnvUtils.ts` 的 `User-Agent: Cline/<version>`；
- Provider 中的 `HTTP-Referer: https://cline.bot`；
- Documentation、Privacy、Dashboard、Discord/GitHub 链接；
- `@cline.bot` 内部账号判断；
- Bug Report、Support、Telemetry 页面；
- 更新公告和 Marketplace URL。

这些不一定影响本地安装，但会影响产品身份、服务路由和合规。

## 12. Proto Package 是否需要重命名

### 12.1 本地独立插件：不需要

`cline.TaskService`、`proto/cline` 和 `ClineMessage` 是内部协议名。两个 VS Code 扩展各自 Bundle，不会因 Proto Package 同名而冲突。

保留它们可以显著减少改动面，也方便继续合并上游更新。

### 12.2 完全独立协议：可以，但代价很高

如果外部公开 gRPC API 也要改名，需要：

- 修改全部 `.proto` package/service；
- 修改生成脚本对 `cline.*` 的过滤和映射；
- 修改 Controller Handler Map；
- 修改 Testing Platform；
- 修改 External Clients；
- 重新生成所有 Proto；
- 提供旧协议迁移或版本化。

建议把 Proto 改名放到产品稳定后的独立阶段，不要与第一次 VSIX 改名一起做。

## 13. 更新 README、License 与发布信息

### 13.1 README

当前 `README.md` 为空，Marketplace 内容来自 `README.marketplace.md`。独立插件应：

- 编写自己的 `README.md`；
- 更新 `README.marketplace.md`；
- 更新 `scripts/marketplace-readme.mjs` 的说明；
- 移除官方 Cline 截图、链接和安装说明；
- 说明数据目录、模型 Key、Telemetry 和网络请求。

### 13.2 License

项目使用 Apache-2.0。Fork 时通常需要：

- 保留 LICENSE；
- 保留适用的版权和 Notice；
- 标明基于 Cline 修改；
- 不使用原商标暗示官方关系；
- 检查新增依赖、图标、字体和品牌资产的许可。

这不是法律意见；正式商业发布前应让专业人员复核许可证与商标使用。

## 14. 更新 `.vscodeignore`

当前 `.vscodeignore` 会排除源码和测试，但不会自动排除新建的 `教程` 目录。生产 VSIX 通常不需要这些内部分析文档，可加入：

```text
教程/**
```

还应检查：

- 新 Logo/Icon 是否被包含；
- `webview-ui/build` 是否未被排除；
- `dist/extension.js` 是否包含；
- Source Map、测试、录制数据是否排除；
- `.env`、Token、私有 Endpoint 配置绝不打包；
- 已删除的 Cline 资产不再进入 VSIX。

查看最终文件列表：

```bash
npx vsce ls
```

## 15. 构建独立插件

## 15.1 清理并重新安装

品牌改造完成后建议做一次干净构建：

```bash
npm run clean:build
npm run install:all
npm run protos
```

通常不需要每次删除 `node_modules`；只有锁文件、Node 版本或原生模块异常时再运行 `npm run clean:deps`。

## 15.2 类型、测试和生产构建

```bash
npm run check-types
npm run lint
npm run test:unit
npm run test:webview
npm run package
```

`npm run package` 应生成：

```text
dist/extension.js
webview-ui/build/assets/index.js
webview-ui/build/assets/index.css
```

## 15.3 生成 VSIX

```bash
mkdir -p dist
npx vsce package --out dist/my-agent-0.1.0.vsix
```

VSCE 会读取 `package.json` 并执行 `vscode:prepublish`，当前该脚本会再次运行生产构建。

如果 VSCE 报告某个明确的构建时 Secret 名称，优先从源码和打包内容移除该 Secret；只有确认它不是实际凭据时，才使用定向的 `--allow-package-secrets <name>`，不要使用宽泛跳过安全检查。

检查文件：

```bash
ls -lh dist/my-agent-0.1.0.vsix
npx vsce ls
```

## 16. 本地安装到 VS Code

### 16.1 命令行安装

```bash
code --install-extension "$PWD/dist/my-agent-0.1.0.vsix" --force
```

如果使用 VS Code Insiders：

```bash
code-insiders --install-extension "$PWD/dist/my-agent-0.1.0.vsix" --force
```

### 16.2 UI 安装

1. 打开 VS Code；
2. 打开 Extensions；
3. 点击右上角 `...`；
4. 选择 `Install from VSIX...`；
5. 选择 `dist/my-agent-0.1.0.vsix`；
6. Reload Window。

### 16.3 验证安装 ID

```bash
code --list-extensions --show-versions | rg '^mycompany\.my-agent@'
```

预期类似：

```text
mycompany.my-agent@0.1.0
```

### 16.4 卸载

```bash
code --uninstall-extension mycompany.my-agent
```

## 17. 本地冒烟测试

安装后至少验证：

## 18. 与官方 Cline 并存的必要条件

要真正并存，至少必须不同：

```text
publisher.name
Activity Bar Container ID
Sidebar View ID
Command Prefix
Comment Controller ID
Context Keys
Global Data Directory
OAuth Redirect Extension ID
```

如果只改 `publisher.name`，虽然 VS Code 会把它视为不同扩展，但两个扩展仍可能：

- 竞争同一个 Command ID；
- 竞争同一个 View ID；
- 共用 `~/.cline` 状态和 Secret；
- OAuth 回调到官方扩展；
- 同时监听同一 Rules/MCP 文件；
- 向同一遥测项目上报。

## 19. 常见失败及排查

### 19.1 Sidebar 显示“No view is registered”

原因：`package.json` View ID 与 `ExtensionRegistryInfo.views.Sidebar` 不一致。

检查：

```text
package name = my-agent
package view id = my-agent.SidebarProvider
registry result = my-agent.SidebarProvider
```

### 19.2 点击按钮提示 Command Not Found

原因：Package/Menu 仍引用 `cline.*`，代码已注册 `my-agent.*`，或反之。

执行：

```bash
rg -n 'cline\.|my-agent\.' package.json src
```

逐项核对 Command 声明、注册和 Menu 引用。

### 19.3 Webview 白屏

检查：

- `webview-ui/build/assets/index.js`；
- `index.css`；
- Webview Developer Tools Console；
- CSP 的 connect/style/script/img 域名；
- Vite 开发端口；
- `localResourceRoots`。

### 19.4 找不到 `@generated`

运行：

```bash
npm run protos
```

不要手工创建空生成文件。

### 19.5 OAuth 登录后打开官方 Cline

检查 `getIdeRedirectUri.ts`、`context.extension.id`、网页 OAuth Client Redirect 配置和服务端允许的 Extension ID。

### 19.6 两个插件状态互相覆盖

检查 `StorageContext`、`CLINE_DIR`、Secrets/Distinct ID、MCP/Rules/Skills 目录是否仍共享。

### 19.7 VSIX 太大

运行：

```bash
npx vsce ls
du -sh dist webview-ui/build node_modules
```

检查 `.vscodeignore`，同时确认 esbuild 已 Bundle 运行依赖，不要无条件把整个 `node_modules` 打入 VSIX。

### 19.8 安装后还是旧版本

修改 `package.json.version`，重新 Package，并：

```bash
code --install-extension dist/my-agent-0.1.1.vsix --force
```

然后执行 `Developer: Reload Window`。View Container ID 被 VS Code 缓存时，可能需要卸载旧扩展并重新加载 Profile。

## 24. 最终建议

最稳妥的落地路线是：

```text
先改 Extension Identity
  -> 修复 Command/View/OAuth 硬编码
  -> 替换 UI 品牌
  -> 生成并安装 VSIX
  -> 隔离数据目录
  -> 关闭原遥测
  -> 再替换 Auth/Backend/MCP Marketplace
```

判断是否真正成为“自己的独立插件”的标准，不是界面上是否显示新名字，而是：

> **VS Code 身份、命令与视图、OAuth、数据目录、网络端点、遥测项目和品牌资产都拥有独立边界，并且可以与官方插件同时安装而互不影响。**
