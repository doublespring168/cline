# VS Code 单插件化与非核心功能剥离

> 更新时间：2026-07-15。本文描述当前源码已经完成的删除结果，不是待办清单。

## 1. 当前产品边界

当前项目只面向 VS Code 插件形态：插件运行在 VS Code Extension Host 中，Webview 提供聊天界面，Agent 可连接模型、读写代码、执行终端、调用 MCP/Skills/Hooks/Subagents 等开发能力。

本轮进一步删除了四类与“本地写代码智能体”无关或可产生远程数据面的功能：

1. 遥测、远程错误上报和远程特性开关；
2. 云端聊天记录/Prompt 同步；
3. Banner、版本公告和商业推广；
4. Cline Account、组织、额度、订阅和 ClinePass。

## 2. 遥测、远程错误上报和特性开关

已删除：

- PostHog Node/Web 客户端、Provider、Factory 和测试；
- OpenTelemetry Logs/Metrics/Trace、OTLP/Prometheus Exporter、配置和测试；
- 远程错误 `ErrorService`、PostHog Error Provider 和自动捕获配置；
- Feature Flag Service、PostHog Feature Flag Provider、前端 `useFeatureFlag`；
- Telemetry Setting、HostBridge 遥测 RPC、设置页遥测开关；
- 构建期 PostHog/OTel/Error 环境变量注入；
- `posthog-node`、`posthog-js`、Firebase 和全部 `@opentelemetry/*` 依赖。

`src/services/telemetry/index.ts`、生产调用点和仅为遥测计算的中间指标均已删除，不再保留 no-op 门面。源码中少量包含 “telemetry” 的注释仅用于说明旧设计或禁止第三方 CLI 上报，不代表存在遥测客户端。

Web Tools、Worktrees 和 Multi-root 的可用性现固定为本地能力，用户开关直接生效。OpenAI Responses WebSocket 原远程开关已固定关闭。

## 3. 云端聊天记录同步

已删除：

- `src/shared/services/worker` 的 Queue、Worker、Backfill 和 Sync；
- S3、R2、Azure Blob adapters；
- `ClineBlobStorage`、Blob 配置 State/Proto；
- Prompt Upload、连接测试和企业遥测 Schema；
- Remote Config 中的遥测/上传配置；
- 云同步专用测试。

`saveApiConversationHistory()` 现在只写本地任务目录。内置代码不会自动把 `api_conversation_history.json`、`ui_messages.json`、附件或工具记录上传到 Cline 云端。

边界说明：发送给模型 Provider 的当前 Context 仍然是模型推理所需的正常 API 请求；用户配置的 MCP、Hook、模型 Provider 或自定义工具也可能自行联网，它们不属于已删除的“聊天记录云同步”。

## 4. Banner、公告和商业推广

已删除：

- `BannerService`、Banner Proto/RPC、Dismiss/Track/Version State；
- `BannerCarousel`、`TelemetryBanner`、`WhatsNew` Modal/Items；
- Announcement 状态、显示事件和工具函数；
- Welcome/Onboarding 中的账号创建、ClinePass 订阅和商业卡片；
- Account、Credit、Spend Limit、Entitlement、ClinePass Limit 等商业错误卡；
- VS Code Account View Title 按钮和 Navbar Account 入口。

OCA 模型选择器不再渲染服务返回的 `banner` 内容或确认弹窗；OCA 登录、Token 刷新和模型列表仍作为模型专属认证能力保留。

## 5. Cline Account 体系

已删除：

- `ClineAuthProvider`、`AuthService`、`ClineAccountService`；
- Access/Refresh Token 恢复和跨窗口 `cline:clineAccountId` 监听；
- `/auth` Cline Account URI 回调；
- Account Controller RPC：登录、退出、用户/组织、Credits、Usage、额度申请等；
- Webview `ClineAuthContext`、Account 页面、组织切换和积分 UI；
- `cline-pass` Provider、模型字段、Proto enum、静态模型表和测试；
- Cline Account/ClinePass E2E Mock 路由。

普通 `cline` Provider 仍保留，但认证方式改为显式 `clineApiKey`：

```text
Settings / Onboarding
  → ClineProvider ApiKeyField
  → StateManager.setSecret("clineApiKey")
  → ~/.cline/data/secrets.json（0600）
  → ClineHandler Authorization: Bearer <clineApiKey>
```

没有 Key 时，前后端均显示普通 API Key 配置错误，不再提示“登录 Cline”。

## 6. 必须保留的模型/工具专属认证

以下认证不是 Cline Account，已保留：

| 认证 | 用途 | 主要源码 |
| --- | --- | --- |
| OCA OAuth | OCA 模型 | `services/auth/oca`、`core/controller/ocaAccount` |
| OpenRouter OAuth | 换取 OpenRouter API Key | Account Proto 中的模型认证 RPC、OpenRouter Provider UI |
| Requesty OAuth | Requesty 模型 | Requesty callback/Provider |
| HiCap OAuth | HiCap 模型 | HiCap callback/Provider |
| OpenAI Codex OAuth/PKCE | ChatGPT Codex Backend | `integrations/openai-codex`、Account Proto 的 Codex RPC |
| MCP OAuth | MCP Server | `services/mcp/McpOAuthManager.ts`、`/mcp-auth/callback/<hash>` |
| AWS/Azure/Vertex 等凭据 | 对应云模型 | 各 Provider 与本地 Secret/SDK Credential Chain |

`proto/cline/account.proto` 名称暂时保留，但内容只剩上述模型专属认证 RPC，不能据文件名判断 Cline Account 仍存在。

## 7. 仍保留的核心能力

- VS Code Sidebar/Webview、Extension Host 生命周期和本地调试；
- 多模型 Provider、Plan/Act、Reasoning、Tool Calling、Streaming；
- 文件、Diff、Diagnostics、终端、Git、Checkpoint；
- MCP、Skills、Rules、Workflows、Hooks、Subagents；
- Browser 工具、显式 `@url` 内容引用、Worktrees、多根工作区；
- 本地任务历史、Context 管理、JSON 存储；
- VS Code LM、Notebook、SCM、Comments 等 IDE 集成。

这些能力与本地写代码智能体目标直接相关，未在本轮删除。

## 8. 本轮继续移除的 VS Code 非必要外围

在保持 VS Code 写代码智能体主链路、全部模型 Provider、模型专属认证和 MCP Runtime 的前提下，进一步删除：

- Extension 集成测试专用 `TestMode`、`TestServer`、`GitHelper` 和 gRPC Recorder；
- 对第三方扩展暴露的 `src/exports` Cline API；
- LG Task/Webhook 集成；
- Walkthrough、Quick Wins、Feature Tips、Task Feedback 和 Report Bug 产品入口；
- 独立 `web_fetch`、`web_search` 工具及 Handler；保留 Browser 与用户显式 `@url` 引用；
- MCP Marketplace 浏览、下载、缓存、Proto/RPC/UI 和远程组织管控；保留 stdio/SSE/Streamable HTTP、OAuth、工具/资源/Prompt、通知与自动批准；
- Remote Config 的联网逻辑、Schema、状态字段和所有兼容空分支；
- Tree-sitter Runtime、Queries、WASM、依赖和构建复制逻辑，代码定义查询改用 VS Code Document Symbol Provider；
- 已失去消费者的 `mcpBaseUrl` Endpoint 字段和仅服务遥测的文件系统分类工具。

## 9. 测试和构建结果

本轮实际验证：

```bash
npm run check-types       # 通过
npm run lint              # 通过
npm run test:unit         # 1278 passing, 4 pending
npm run test:webview      # 19 files, 150 tests passing
npm run test:integration  # Extension Host 冒烟启动成功，退出码 0
npm run package           # Proto + TS + Vite + Biome + esbuild 通过
npm run test:e2e:build    # Node 22 下成功生成 dist/e2e.vsix
npx playwright test src/test/e2e/auth.test.ts --project='e2e tests' --retries=0
                           # 本地 API Key Onboarding + Setup 共 2 项通过
```

集成测试当前输出 `0 passing`，仅证明测试版 VS Code 和 Extension Host 能启动/退出；本轮另外验证了本地 API Key Onboarding 的 Playwright E2E。其他真实交互仍应通过完整 E2E 和手工 Extension Development Host 验证。

## 10. 有意保留的边界

- Browser、Hooks、Worktrees、Subagents、Skills、Checkpoints、多根工作区和 MCP Runtime 暂不剥离；
- OCA、OpenRouter、Requesty、HiCap、OpenAI Codex、MCP OAuth 以及云厂商 Credential Chain 必须保留；
- `proto/cline/account.proto` 仅承载模型专属认证 RPC，名称保留是为了避免无意义的协议文件迁移；
- `ModelInfo.banner` 仍可能存在于通用模型元数据类型中，但当前产品 UI 不再把它作为公告或推广展示。

## 11. 结论

当前源码已经不具备 Cline 账号会话、组织/额度/订阅、商业 Banner、公告轮播、PostHog/OTel 遥测、远程错误 Provider、Feature Flag 拉取或对象存储聊天同步能力。插件仍能通过本地配置的模型 Key 和模型专属 OAuth 连接各 Provider，继续作为 VS Code 写代码智能体运行。
