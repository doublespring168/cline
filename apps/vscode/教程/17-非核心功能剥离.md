# VS Code 单插件化与非核心功能剥离

> 更新时间：2026-07-15。独立 Core/跨宿主运行形态已经从当前工程删除。本文同时记录已完成项、保留边界和后续仍可选择剥离的功能。

## 1. 当前目标形态

当前项目只保留这一条运行链：

```text
VS Code
  -> Extension Host 加载 dist/extension.js
  -> extension.ts 初始化 HostProvider
  -> common.ts 创建 Controller/State/服务
  -> Webview 加载 webview-ui/build
  -> Controller -> Task -> Provider/Tool
  -> VS Code 文件、Diff、Terminal、Diagnostics 等能力
```

不会生成或启动第二个 Core 服务，不监听 Core gRPC 端口，也不需要外部 Host Bridge 进程。

## 2. 已完成删除

### 2.1 独立 Core 和外部宿主

已删除：


同时删除了外部宿主 OAuth HTTP 回调服务器、独立 Webview/Diff/Comment Review 适配器、Host Bridge Client Manager 和独立进程生命周期代码。

### 2.2 独立终端和后台执行模式

## 3. 当前保留的核心能力

如果目标是“安装为 VS Code 插件、连接模型、作为编码智能体”，以下能力属于核心：

| 能力 | 主要源码 | 是否保留 |
| --- | --- | --- |
| 扩展激活和命令注册 | `src/extension.ts`、`src/common.ts`、`src/registry.ts` | 必须 |
| Webview 聊天界面 | `webview-ui/src`、`src/hosts/vscode/VscodeWebviewProvider.ts` | 必须 |
| Agent 循环 | `src/core/controller`、`src/core/task` | 必须 |
| 模型 Provider | `src/core/api`、`src/shared/api.ts` | 必须 |
| Prompt/Context | `src/core/prompts`、`src/core/context` | 必须 |
| 文件读写和 Diff | `src/core/task/tools`、`src/integrations/editor` | 必须 |
| VS Code 终端 | `src/hosts/vscode/terminal`、`src/integrations/terminal` | 必须 |
| 状态/密钥/历史 | `src/core/storage`、`src/shared/storage` | 必须 |
| ProtoBus | `proto/cline`、生成脚本、Webview Client | 必须 |
| VS Code HostBridge | `proto/host`、`src/hosts/vscode/hostbridge` | 必须 |

## 4. 尚可按产品目标继续剥离

以下功能不是独立运行形态，本次有意保留；如果你的产品不需要，可以另开改造任务逐项删除：

### 4.1 商业账号与云服务

- Cline Account/Cline Pass；
- 组织策略和远程配置；
- Banner、Feature Flag、PostHog、OpenTelemetry；
- Prompt Upload/S3 企业遥测。

删除前要给模型配置、认证和错误处理提供本地替代路径。

### 4.2 浏览器、MCP、Worktree

- 浏览器自动化和截图；
- MCP Marketplace、OAuth、Server 管理；
- Git Worktree 管理和并行任务入口。

这些功能与 Tool Schema、设置页、Proto、Prompt 和历史消息都有交叉，不能只删一个 UI 组件。

### 4.3 Hooks、Skills、Subagents

它们属于编码智能体扩展能力。若目标是最小 Agent，可以删除；若需要可扩展自动化，建议保留。

### 4.4 非目标 Provider

可以只保留实际需要的模型 Provider，但必须同步处理：

- `ApiProvider` 联合类型；
- `buildApiHandler()` 工厂；
- 模型目录和默认值；
- Settings/Onboarding Provider UI；
- Secret/State keys；
- Provider 单元测试和文档。

## 5. 不应误删的内容

- `@grpc/grpc-js`：仍被 OpenTelemetry gRPC 导出使用；
- `undici`：部分模型连接和 WebSocket/HTTP 客户端仍使用；
- `vscode-uri`：核心路径/URI 逻辑仍有引用；
- `proto/cline`：Webview 与 Extension Host 的类型化消息契约；
- `proto/host`：核心调用 VS Code 能力的本地接口；
- `HostProvider`：虽然只剩 VS Code 实现，仍是宿主能力的统一初始化和测试边界；
- `backgroundEditEnabled`：与已删除的后台终端不是同一功能。

## 6. 当前构建与运行结论

打包后的 VSIX 只有一个扩展入口：

```json
"main": "./dist/extension.js"
```

安装后 VS Code 会在 Extension Host 中加载它。Webview 运行在 VS Code 管理的 Webview Renderer 中；模型 SDK、浏览器或 Hook 可能按各自功能创建网络连接或子进程，但不会启动第二个 Cline Core 服务。

## 8. 后续改造建议

下一阶段不要再以“运行形态”为单位清理，而应按产品能力切片：

1. 先确定需要保留的模型 Provider；
2. 再决定 MCP、浏览器、Worktree、Hooks、Skills、Subagents；
3. 再决定账号、云配置和遥测；
4. 每删除一个切片，同步 Proto、State、Webview、Prompt、测试和教程；
5. 每阶段都生成 VSIX，在 Extension Development Host 和手动安装环境各验证一次。

这样可以保持插件始终可运行，避免再次出现“目录删除了但生成代码、状态字段或 UI 仍引用”的半清理状态。
