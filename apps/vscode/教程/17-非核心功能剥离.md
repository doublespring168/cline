结论：如果你的目标明确为“普通 VS Code 插件 + 用户自行配置模型 + 编码智能体”，当前项目中 Standalone/跨宿主、Cline 商业账号、云端同步、遥测、MCP、浏览器自动化、Worktree、Hooks/Subagent 等大量功能都可以剥离。

我建议采用“精简但安全”的版本，而不是只剩聊天框的极限版本：

```text

├─ React 聊天和模型设置
├─ Controller / Task / Agent 主循环
├─ 多模型 Provider 适配层
├─ Context 与会话持久化
├─ 文件读取、搜索、修改
├─ VS Code Diff
├─ 终端命令执行
├─ 用户审批和权限控制
└─ Checkpoint 回滚
```

以下分析假设你主要使用自己的 API Key/Base URL，不依赖 Cline 平台充值、积分和订阅。

## 九、正确的裁剪顺序

1. 先确定完整 Provider 列表，尤其是否保留 `cline`、`cline-pass`、OCA、OpenAI Codex。
2. 建立统一 `FeatureCapabilities` 和工具 Allowlist。
3. 让 Prompt、ToolExecutor 和 Assistant XML 解析器使用同一个工具集合。
4. 先删除 UI 入口、Manifest 命令和远程服务初始化。
5. 将 MCP、Browser、Hooks、Telemetry 等改成 Optional/No-op。
6. 跑通“新任务→模型流→读文件→改文件→执行命令→批准→完成”。
7. 删除对应 Proto RPC 和 Handler。
8. 执行 `npm run protos` 更新生成代码。
9. 删除源码和 npm 依赖。
10. 完成单元、Webview、Extension Host 和 E2E 回归。
11. 打包后用 `vsce ls` 检查最终 VSIX 内容。

工具裁剪尤其需要同步这三个地方：

- [`src/shared/tools.ts`](/Users/darcy/mwp/ala-platform-other/cline/apps/vscode/src/shared/tools.ts:8)；
- [`ToolExecutorCoordinator.ts`](/Users/darcy/mwp/ala-platform-other/cline/apps/vscode/src/core/task/tools/ToolExecutorCoordinator.ts:73)；
- `src/core/assistant-message/parse-assistant-message.ts`。

否则会出现“系统 Prompt 告诉模型有工具，但执行器找不到 Handler”，或者模型输出仍被解析为已经删除的工具。
