# 项目测试与批量执行

> 更新时间：2026-07-15。当前工程已经删除独立 Core、外部宿主回放平台和对应测试脚本，本文件只描述 VS Code 插件保留的测试链路。

## 1. 当前测试分层

| 层级 | 主要位置 | 框架 | 作用 |
| --- | --- | --- | --- |
| 后端单元测试 | `src/**/*.test.ts`、`src/**/__tests__`、`src/test` | Mocha、Sinon、Should/Chai | Provider、Context、Prompt、Tool、State、Hook、存储等 |
| Webview 单元测试 | `webview-ui/src/**/*.test.*`、`*.spec.*` | Vitest、Testing Library、jsdom | React 组件、设置页、消息渲染、输入交互 |
| VS Code 集成测试 | `src/test/suite` | `@vscode/test-cli`、`@vscode/test-electron` | 在 Extension Development Host 中测试扩展激活和 VS Code API |
| Playwright E2E | `src/test/e2e` | Playwright | 启动真实 VS Code/Electron，验证 Webview 和完整交互 |
| 构建验证 | Proto、TypeScript、Biome、Vite、esbuild、vsce | npm scripts | 验证生成代码、类型、风格和 VSIX 内容 |

已删除的测试能力包括：独立 Core gRPC 录制回放、`testing-platform`、`test:tp-orchestrator`、`test:sca-server` 和对应 JSON 录制 Spec。

## 2. 首次准备

在 `apps/vscode` 目录执行：

```bash
npm ci
npm --prefix webview-ui ci
```

建议使用仓库 `.nvmrc` 对应的 Node.js 版本。依赖安装完成后先生成协议代码：

```bash
npm run protos
```

生成器现在只产生：

- `src/shared/proto`；
- `src/generated/hosts/vscode`；
- `src/generated/hosts/host-bridge-client-types.ts`；
- `webview-ui/src/services/grpc-client.ts`。

## 3. 常用测试命令

### 3.1 后端单元测试

```bash
npm run test:unit
```

更新系统提示快照时才使用：

```bash
npm run test:unit -- --update-snapshots
```

不要在没有确认 Prompt 变化合理时盲目更新快照。

### 3.2 Webview 测试

```bash
npm run test:webview
```

等价于进入 `webview-ui` 执行 Vitest。测试输出中的 React DOM nesting、`act(...)` 等 warning 不一定导致失败，但应作为后续质量问题处理。

### 3.3 VS Code 集成测试

```bash
npm run test:integration
```

该命令会下载或复用测试版 VS Code，并在 Extension Host 中加载扩展。测试必须通过正式的扩展激活入口初始化 `HostProvider`；若直接导入依赖宿主的业务模块，可能出现 `HostProvider not setup`。

### 3.4 Playwright E2E

```bash
npm run test:e2e
```

如需查看浏览器/VS Code 窗口和调试日志，应根据 `src/test/e2e` 中的配置关闭 headless，或使用项目已有的 E2E 调试脚本。

## 4. 批量测试推荐顺序

日常提交前：

```bash
npm run check-types
npm run lint
npm run test:unit
npm run test:webview
npm run package
```

涉及激活、命令注册、URI 回调、终端或 VS Code API 时，再增加：

```bash
npm run test:integration
```

涉及完整聊天和 Webview 交互时，再增加：

```bash
npm run test:e2e
```

## 5. `npm run package` 覆盖什么

当前脚本按顺序执行：

1. `npm run check-types`：重新生成 Proto，并检查扩展端与 Webview TypeScript；
2. `npm run build:webview`：生成 `webview-ui/build`；
3. `npm run lint`：运行 Biome 和 Proto lint；
4. `node esbuild.mjs --production`：生成 `dist/extension.js`。

它不执行单元测试、集成测试或 E2E，因此不能替代测试命令。

## 7. 常见故障

### 7.1 Lint 扫描 coverage HTML

覆盖率 HTML 不是源码。若出现 `coverage/.../*.html` 解析错误，应删除旧 coverage 产物或确保 Biome excludes 覆盖该目录，不要修改生成的 HTML。当前 `.vscodeignore` 同时排除了 `coverage/**` 和 `.nyc_output/**`，避免测试产物进入 VSIX。

### 7.2 `HostProvider not setup`

说明测试绕过了 `activate()`/`initialize()`。处理方式是：

- 纯单元测试注入或初始化 HostProvider 测试替身；
- 需要真实 VS Code 能力的测试放入 Extension Host 集成测试；
- 不要把宿主依赖模块当作无环境的纯函数直接加载。

### 7.3 VS Code 下载或 Electron 启动失败

检查网络代理、`.vscode-test` 缓存、macOS 权限和是否已有残留 VS Code 测试进程。CI 中应固定 VS Code 版本，避免环境漂移。

## 8. 修改类型与最低验证集

| 修改类型 | 最低验证 |
| --- | --- |
| Provider/模型协议 | `check-types`、相关单元测试、`package` |
| Prompt/Context/Tool | 单元测试、快照检查、`package` |
| React/CSS/设置页 | `test:webview`、`build:webview`、手工调试 |
| Proto/RPC | `protos`、`check-types`、Handler 测试 |
| VS Code API/激活/命令 | `test:integration`、手工 Extension Development Host |
| 打包清单 | `package`、`npx vsce ls --no-dependencies`、生成 VSIX |

当前项目的批量质量门禁应围绕 VS Code Extension Host，而不是已删除的独立服务进程。
