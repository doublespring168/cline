# 项目测试说明

> 本文基于当前 `apps/vscode` 工作区的测试源码、测试配置、`package.json` 脚本和 CI 流程整理。文中的数量是静态扫描结果，实际执行数量可能因环境、条件分支或测试参数不同而变化。

## 1. 总体结论

项目没有一个覆盖所有测试层的 `test:all` 脚本。当前测试体系可以分为五类：

1. Mocha 后端/核心单元测试；
2. VS Code Extension Host 集成测试；
3. Webview React 组件测试；
4. Playwright VS Code/Electron 端到端测试；
5. Standalone Core 的 gRPC 录制回放测试。

按当前工作树统计：

| 测试层                     |                                               文件或场景数量 | 主要框架/运行环境                         |
| -------------------------- | -----------------------------------------------------------: | ----------------------------------------- |
| 后端与扩展测试（唯一文件） |                                                       165 个 | Mocha、ts-node，或 VS Code Extension Host |
| Mocha 单元测试             | 119 个测试文件（配置共匹配 123 个文件，其中 4 个为辅助文件） | Mocha + Chai/Sinon 等                     |
| VS Code 集成测试           |                                            49 个源码测试文件 | `@vscode/test-cli` + 真实 VS Code       |
| Webview 测试               |                                                        20 个 | Vitest + jsdom + Testing Library          |
| Playwright E2E             |                                4 个文件，展开为 6 个业务场景 | Playwright + VS Code/Electron             |
| gRPC 回放                  |                           1 个 JSON Spec，包含 4 个 RPC 校验 | Standalone Core + testing-platform        |

单元测试和集成测试有 3 个 `src/test/services` 文件重叠执行，所以不能简单地把 119 和 49 相加作为唯一文件数。

## 2. 后端和核心单元测试

### 2.1 测试入口和匹配规则

入口脚本位于 [package.json](/Users/darcy/mwp/ala-platform-other/cline/apps/vscode/package.json:409)，匹配规则位于 [.mocharc.json](/Users/darcy/mwp/ala-platform-other/cline/apps/vscode/.mocharc.json:1)：

```json
{
  "spec": [
    "src/**/__tests__/*.ts",
    "src/test/services/**/*.test.ts"
  ]
}
```

运行时通过 `ts-node/register` 直接执行 TypeScript，并由 `src/test/requires.ts` 对 `vscode` 模块进行测试替身注入，因此这部分测试通常不需要启动真实的 VS Code 窗口。

### 2.2 主要覆盖范围

- API Provider、模型协议转换、消息格式和重试；
- Agent Task、ToolExecutor、工具处理器和 Subagent；
- ContextManager、规则、Skill、文件跟踪和上下文压缩；
- 系统提示词构建、Provider Prompt Variant 和快照；
- Hooks 生命周期、Controller、任务状态和消息流；
- MCP、OAuth、远程配置、存储和工作区；
- Checkpoint、Diagnostics、Telemetry、Diff 和终端工具；
- 权限、路径、多根工作区和通用工具函数。

系统提示词测试还包含快照基线，修改提示词后需要谨慎确认快照变化。

### 2.3 运行方式

```bash

#【注意，注意，注意】切换node版本
nvm use 22

# 全部单元测试
npm run test:unit

# 按测试名称筛选
npm run test:unit -- --grep "ContextManager"

# 生成单元测试覆盖率
npx nyc --nycrc-path .nycrc.unit.json --reporter=lcov npm run test:unit

# 有意更新提示词快照（不要在普通回归测试中随意使用）
UPDATE_SNAPSHOTS=true npm run test:unit

```

单元测试覆盖率输出到 `coverage-unit/`。

## 3. VS Code Extension Host 集成测试

### 3.1 运行方式

配置位于 [.vscode-test.mjs](/Users/darcy/mwp/ala-platform-other/cline/apps/vscode/.vscode-test.mjs:1)。测试会在真实 VS Code Extension Development Host 中运行编译后的 `out/**/*.test.js`，并排除 `src/test/e2e`。

首次直接运行前应先编译扩展和测试：

```bash
npm run ci:build
npm run test:integration
```

本地默认使用 `stable` 版本的 VS Code。与 CI 对齐时固定版本：

```bash
VSCODE_TEST_VERSION=1.103.0 npm run test:integration
```

集成测试覆盖率入口为：

```bash
npm run test:coverage
```

### 3.2 主要覆盖范围

- 扩展激活、命令注册、Webview 和扩展公开 API；
- HostBridge、gRPC 路由和宿主能力适配；
- VS Code 工作区、文件、编辑器、Diff、标签页和 Diagnostics；
- VS Code Terminal、Shell Integration、PowerShell 和命令执行；
- Hooks、消息状态、权限、Mentions 和 Slash Command；
- 认证、模型刷新、任务状态和多根工作区。

该层会共享 Extension Host、测试工作区和扩展状态，不建议同时并行运行多个集成测试进程。

Linux 无图形环境时使用：

```bash
xvfb-run -a npm run test:integration
# 或
xvfb-run -a npm run test:coverage
```

## 4. Webview 测试

Webview 测试位于 `webview-ui`，使用 Vitest、jsdom 和 React Testing Library。主要覆盖：

- 聊天消息、错误、思考内容和工具调用行的渲染；
- `UserMessage` 的输入法（IME）行为；
- 按钮、消息分组和交互状态；
- 设置页、Provider/模型选择器和价格展示；
- Onboarding 数据；
- Mentions、Slash Command、Hooks 和平台工具函数。

运行命令：

```bash
# 全部 Webview 测试
npm run test:webview

# 等价的目录级命令
npm --prefix webview-ui run test

# 覆盖率
npm --prefix webview-ui run test:coverage

# 监听模式
npm --prefix webview-ui run test:watch

# 单文件示例
npm --prefix webview-ui run test -- src/components/chat/__tests__/UserMessage.ime.test.tsx
```

覆盖率输出到 `webview-ui/coverage/`。这层不需要启动完整的 VS Code，但需要先安装 `webview-ui` 依赖。

## 5. Playwright VS Code E2E 测试

测试文件位于 `src/test/e2e/`：

- `auth.test.ts`：登录、API Key 和设置导航；
- `chat.test.ts`：发送聊天、历史、Plan/Act、Slash Command 和 Mention；
- `diff.test.ts`：单根和多根工作区的 Diff Editor；
- `editor.test.ts`：单根和多根工作区的代码选择/Add to Cline。

上述 4 个文件实际展开为 6 个业务测试场景，并先执行 `global.setup.ts`。测试使用真实 VS Code/Electron，但使用本地 Mock Cline API，不需要真实模型 Key；Mock 服务使用固定的 `7777` 端口。配置见 [playwright.config.ts](/Users/darcy/mwp/ala-platform-other/cline/apps/vscode/playwright.config.ts:1)。

### 5.1 运行命令

第一次运行，需要安装 Playwright 浏览器并构建 VSIX：

```bash
npm run test:e2e
```

浏览器已经准备好后，使用 CI/日常回归入口：

```bash
npm run test:e2e:optimal
```

如果 VSIX 和 E2E 构建产物已经存在，可以直接运行：

```bash
npm run e2e
```

筛选和调试：

```bash
npm run e2e -- auth.test.ts
npm run e2e -- --grep "Chat"
npm run e2e -- --debug
npm run e2e -- --headed
```

Linux 无桌面环境：

```bash
xvfb-run -a npm run test:e2e:optimal
```

失败视频和报告位于 `test-results/playwright/`。Playwright 配置固定单 worker，主要原因是每个 worker 会启动 VS Code，并且 Mock API 使用固定端口；不要随意强制提高 `workers` 并发数。

## 6. Standalone Core gRPC 回放测试

测试平台位于 `testing-platform/`，当前测试目录只有一个录制 Spec：

`tests/specs/grpc_recorded_session_single_root.json`

该 Spec 包含 4 个 RPC 检查：

1. `cline.AccountService.accountLoginClicked`；
2. `cline.AccountService.getUserOrganizations`；
3. `cline.TaskService.newTask`；
4. `cline.StateService.getLatestState`。

测试平台会为每个 Spec 启动独立的 Mock API、HostBridge 和 Standalone Core，重放 RPC，并将实际结果与 JSON 期望结果比较；配置的非确定性字段会被忽略，`meta.expected` 可以表达部分断言。

运行前准备：

```bash
npm --prefix testing-platform ci
npm run download-ripgrep
npm run compile-standalone
```

推荐使用编排器批量运行：

```bash
npm run test:tp-orchestrator -- tests/specs/ --count=1
```

增加重复次数、服务日志和覆盖率：

```bash
npm run test:tp-orchestrator -- tests/specs/ --count=3 --server-logs --coverage
```

单个 Spec：

```bash
npm run test:tp-orchestrator -- tests/specs/grpc_recorded_session_single_root.json
```

`--fix` 会改写 golden JSON，只能在明确要更新期望结果时使用。覆盖率会写入类似 `coverage/coverage-core-<port>/` 的目录。

## 7. 批量测试方案

### 7.1 只跑常规后端回归

```bash
npm test
```

`npm test` 会自动先执行 `pretest`：

```text
compile
compile-tests
compile-standalone

```

之后串行执行：

```text
test:unit
test:integration
```

它不包含 Webview、Playwright E2E 和 testing-platform。

### 7.2 推荐的 CI-like 全量流程

在 macOS 或 Windows 上可以按以下顺序执行：

```bash
# 静态质量检查
npm run ci:check-all

# 构建扩展、Webview 和测试
npm run ci:build

# 单元测试覆盖率
npx nyc --nycrc-path .nycrc.unit.json --reporter=lcov npm run test:unit

# VS Code 集成测试覆盖率
npm run test:coverage

# Webview 测试覆盖率
npm --prefix webview-ui run test:coverage

# Playwright E2E
npm run test:e2e:optimal

# Standalone Core gRPC 回放
npm run download-ripgrep
npm run compile-standalone
npm run test:tp-orchestrator -- tests/specs/ --count=1 --coverage
```

Linux 无图形环境时，把需要启动 VS Code 的步骤改为：

```bash
xvfb-run -a npm run test:coverage
xvfb-run -a npm run test:e2e:optimal
```

### 7.3 日常开发的分层执行建议

普通核心逻辑或 Webview 修改：

```bash
npm run test:unit
npm run test:webview
```

涉及 VS Code API、HostBridge、终端、编辑器或工作区：

```bash
npm run ci:build
npm run test:integration
```

提交前再补跑 E2E 和 gRPC 回放测试。Extension Host 测试、E2E 和 gRPC 编排器不建议同时并行，以避免 VS Code 状态、端口和临时工作区互相影响。

## 8. 环境和常见问题

### 8.1 Node.js 版本

仓库 `.nvmrc` 和 CI 使用 Node.js 22。建议不要使用 Node 24 直接判断测试失败是否为代码问题。

### 8.2 依赖安装

根目录、`webview-ui` 和 `testing-platform` 分别有自己的依赖和 lockfile。完整测试前至少执行：

```bash
npm ci
npm --prefix webview-ui ci
npm --prefix testing-platform ci
```

如果只跑根目录单元测试和集成测试，可以暂时不安装 `testing-platform`；运行 gRPC 回放时必须安装。

### 8.3 直接运行集成测试

`npm run test:integration` 不会自动执行顶层 `pretest`。干净工作区应先执行：

```bash
npm run ci:build
```

### 8.4 GUI 和系统库

Linux CI 或无桌面服务器需要 `xvfb`，并可能需要 GTK、NSS、音频等 VS Code 运行库。具体系统依赖可参考仓库的 `CONTRIBUTING.md` Linux setup 章节。

### 8.5 测试结果和覆盖率位置

| 内容                     | 默认位置                           |
| ------------------------ | ---------------------------------- |
| 单元测试覆盖率           | `coverage-unit/`                 |
| Webview 覆盖率           | `webview-ui/coverage/`           |
| Playwright 失败视频/报告 | `test-results/playwright/`       |
| Standalone Core 覆盖率   | `coverage/coverage-core-<port>/` |

## 9. 当前没有纳入常规批量测试的内容

项目中还存在评测/Smoke Test 相关脚本，但它们可能调用真实 CLI、模型和认证服务，可能产生费用，且不属于上述默认回归链路。除非正在进行评测或模型验收，不建议把它们直接混入日常 `npm test` 批量执行。

结论：这个项目有 5 类测试，当前没有统一的 `test:all` 命令。`npm test` 只覆盖后端单元测试和 VS Code 集成测试，并不包含 Webview、Playwright E2E 和 gRPC 回放测试。
