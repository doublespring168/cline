作为团队成员，你可以将本地开发环境连接到组织的 LiteLLM 代理设置。本指南将引导你在 VS Code 中配置连接，以便通过组织的统一代理接口开始使用多个 AI 模型。管理员已经配置好了提供商设置——你只需添加凭据即可开始使用。

## 开始之前

要成功连接到组织的 LiteLLM 代理，你需要提前准备好几项内容。

**已安装并配置 Cline 扩展**  
必须在 VS Code 中安装 Cline 扩展，并且你需要登录组织账号。如果尚未安装 Cline，请参阅我们的[安装指南](/getting-started/installing-cline)。

<Info>
**快速检查**：在 VS Code 中打开 Cline 面板。如果左下角显示了组织名称，就说明你已正确登录。
</Info>

**组织 LiteLLM 代理的访问凭据**  
你需要凭据才能访问组织的 LiteLLM 代理。凭据可能是 API 密钥，也可能是代理已配置为允许从网络内部开放访问。

<Note>
如果你不确定需要哪些凭据，请咨询管理员或 IT 团队，了解如何访问组织的 LiteLLM 代理。
</Note>

## 配置步骤

<Steps>
<Step title="打开 Cline 设置">
打开 VS Code，并使用以下任一方式访问 Cline 设置面板：

- 点击 Cline 面板中的设置图标 (⚙️)
- 点击聊天区域正下方的 API 提供商下拉菜单（它将显示为 `LiteLLM` 或显示具体的模型名称）

</Step>

<Step title="配置 LiteLLM 连接">
LiteLLM 配置选项取决于组织设置代理的方式：

<AccordionGroup>
<Accordion title="API 密钥身份验证">
如果组织要求使用 API 密钥进行身份验证：

1. 选择或确认已选择 **LiteLLM** 提供商
2. 在 **API 密钥**字段中输入分配给你的 API 密钥
3. 基础 URL 应已由管理员配置
4. 点击**保存**以存储凭据

<Tip>
API 密钥存储在 VS Code 本地，并且仅供 Cline 扩展使用。
</Tip>
</Accordion>

<Accordion title="开放访问（无身份验证）">
如果 LiteLLM 代理已配置为允许从网络内部开放访问：

1. 选择或确认已选择 **LiteLLM** 提供商  
2. 将 API 密钥字段留空
3. 扩展将直接连接到已配置的代理端点
4. 无需额外的身份验证

<Info>
当 LiteLLM 代理部署在安全的网络环境中时，通常会采用开放访问。
</Info>
</Accordion>

<Accordion title="自定义配置">
如果组织使用自定义身份验证或特定的连接参数：

1. 遵循管理员提供的任何自定义说明
2. 如果遇到连接问题，请联系 IT 团队
3. 可能需要在 VS Code 之外进行其他配置

<Note>
自定义配置可能需要特定的网络设置或额外的身份验证步骤。
</Note>
</Accordion>
</AccordionGroup>
</Step>

<Step title="选择可用模型">
连接后，你将看到可通过组织 LiteLLM 代理使用的模型：

- 在模型下拉菜单中查看可用模型
- 模型由管理员的代理配置决定  
- 你可以针对不同类型的任务切换模型
- 某些模型可能会根据你的访问级别受到限制

<Tip>
**模型选择**

根据任务要求选择模型：
- 对于快速响应，使用**快速模型**（如 GPT-3.5-turbo）
- 对于复杂推理，使用**强大模型**（如 GPT-4）
- 使用**专用模型**进行代码生成或处理特定领域
</Tip>
</Step>

<Step title="测试连接">
在 Cline 中发送一条测试消息，验证与 LiteLLM 代理的连接能否正常工作。

<Tip>
**测试建议**

先在计划模式下测试连接，验证一切正常后再将其用于实际开发任务。
</Tip>
</Step>
</Steps>

## 模型使用

### 可用的模型类别
通过 LiteLLM 代理可用的模型通常包括：

**文本生成模型：**
- OpenAI GPT-4、GPT-3.5-turbo 变体
- Anthropic Claude 3 Sonnet、Haiku、Opus
- Llama 2、Mistral 等开源模型

**代码专用模型：**
- 用于代码的 OpenAI GPT-4
- CodeLlama 变体
- 专用代码补全模型

**多模态模型：**
- 用于图像分析的 GPT-4 Vision
- 具备视觉能力的 Claude 3 模型

### 模型选择策略
根据开发需求选择模型：

- **快速迭代**：使用速度更快、经济高效的模型
- **复杂问题**：使用更强大的模型  
- **代码密集型任务**：使用代码专用模型
- **视觉内容**：处理图像时使用多模态模型

## 故障排除

**LiteLLM 未作为提供商选项显示**  
确认你已登录正确的 Cline 组织。验证管理员已保存 LiteLLM 配置，并且你使用的是最新版本的 Cline 扩展。

**连接错误或超时**  
验证你的网络能否访问 LiteLLM 代理端点。向 IT 团队确认防火墙规则或 VPN 要求。确保开发环境可以访问代理端点。

**身份验证失败**  
如果使用 API 密钥身份验证，请验证密钥是否输入正确且尚未过期。请联系管理员，确认密钥有效且具备适当权限。

**模型未加载或受到限制**  
可用模型取决于组织的 LiteLLM 配置。如果你需要访问特定模型，或预期的模型不可用，请联系管理员。

**响应时间过长**  
响应时间取决于所用模型和代理负载。对于常规任务，可尝试切换到速度更快的模型。如果性能持续不佳，请联系管理员。

**特定模型返回错误消息**  
某些模型可能暂时不可用或存在特定限制。请尝试其他模型；如果特定模型持续失败，请联系管理员。

## 安全最佳实践

使用组织的 LiteLLM 代理时：

- 妥善保管 API 凭据，不要与他人共享
- 根据数据的敏感程度使用适当的模型  
- 遵循组织的使用准则
- 报告任何可疑活动或未经授权的访问尝试
- 定期更新 Cline 扩展以获取安全补丁

组织管理员负责控制可用模型和使用策略。扩展会根据代理配置和你的访问级别自动显示可用模型。
