YOLO 模式使 Cline 能够完全自主运行，无需用户确认即可自动批准所有操作。对于 Enterprise 管理员，本页介绍如何控制整个组织对 YOLO 模式的访问。

<Note>
有关 YOLO 模式的功能、风险和最佳实践的完整详情，请参阅[功能中的 YOLO 模式](/features/yolo-mode)。
</Note>

## 概述

启用 YOLO 模式后，Cline 会自动批准所有操作，包括文件更改、终端命令、浏览器操作和模式转换。这可提供最高的自动化速度，但会移除所有安全防护措施。

<Warning>
YOLO 模式功能强大，但可能很危险。管理员应仔细考虑哪些团队或用户应有权访问此功能。
</Warning>

## Enterprise 管理员配置

作为 Enterprise 管理员，您可以通过远程配置控制组织中的用户能否启用 YOLO 模式。

### 为所有用户禁用 YOLO 模式

将以下内容添加到您的远程配置 JSON 中：

```json
{
  "yoloModeAllowed": false
}
```

当 `yoloModeAllowed` 设置为 `false` 时：
- 所有用户界面中的 YOLO 模式开关均被禁用
- 即使在本地设置中，用户也无法启用 YOLO 模式
- 此策略会立即应用于所有团队成员
- 企业策略优先于个人偏好

### 为所有用户启用 YOLO 模式

```json
{
  "yoloModeAllowed": true
}
```

当 `yoloModeAllowed` 设置为 `true` 或省略时：
- 用户可以在本地 Cline 设置中启用或禁用 YOLO 模式
- 各个用户可以自行决定是否使用 YOLO 模式
- 不适用任何组织限制

## 企业策略建议

### 推荐方法

出于以下原因，大多数组织应**默认禁用 YOLO 模式**：

<AccordionGroup>
  <Accordion title="安全与合规" icon="shield">
    YOLO 模式会移除所有批准关卡，可能导致：
    - 对关键系统进行未经审查的代码更改
    - 在无人监督的情况下执行命令
    - 可能违反合规策略的自动化操作
    - 通过未受监控的操作导致数据暴露风险
  </Accordion>
  
  <Accordion title="代码质量控制" icon="code">
    没有批准提示时：
    - 更改发生得太快，无法实时审查
    - 错误可能在被发现前不断累积
    - 质量关卡会被绕过
    - 回滚变得更加复杂
  </Accordion>
  
  <Accordion title="审计要求" icon="clipboard-check">
    许多行业要求：
    - 为代码更改提供有记录的批准轨迹
    - 对自动化操作明确问责
    - 可追溯的决策流程
    - YOLO 模式可能与这些要求冲突
  </Accordion>
</AccordionGroup>

### 例外：何时允许 YOLO 模式

可考虑为以下情况启用 YOLO 模式：

**沙盒/开发环境**
- 隔离的测试环境
- 个人开发机器
- 概念验证项目
- 临时探索性工作

**专业角色**
- DevOps 自动化工程师（配备适当监控）
- 沙盒环境中的研发团队
- 具备可靠回滚和恢复流程的团队

**受控用例**
- 具有全面日志记录的脚本化 CI/CD 流水线
- 自动化测试场景
- 演示或培训环境

## 企业注意事项

### 安全影响

在您的组织中启用 YOLO 模式时：

**风险因素：**
- 所有工具执行都会自动进行，无需人工审查
- 错误可能迅速传播到多个文件
- 在实施前发现安全漏洞的机会减少
- 自动化操作可能绕过现有安全控制

**缓解措施：**
- 实施全面的日志记录和监控
- 将 YOLO 模式限制在非生产环境中
- 要求使用 YOLO 模式的团队定期进行安全审查
- 确保已设置版本控制和回滚流程

### 监控要求

在组织中允许 YOLO 模式时，请实施：

**强制监控：**
1. **实时活动跟踪**
   - 监控哪些用户启用了 YOLO 模式
   - 跟踪 YOLO 模式何时处于活动状态
   - 记录执行的所有自动化操作

2. **审计轨迹维护**
   - 保留 YOLO 模式会话的完整历史记录
   - 记录自动执行了哪些操作以及执行时间
   - 为合规目的保留记录

3. **异常检测**
   - 针对不寻常的自动化操作模式发出警报
   - 标记自动执行的高风险操作
   - 监控潜在安全事件

### 监控 YOLO 模式用量

通过策略启用 YOLO 模式后，使用以下方式跟踪用量：

**遥测事件：**
- 捕获用户开启/关闭 YOLO 模式的时间
- 记录启用 YOLO 模式时执行了哪些任务
- 提供整个组织的汇总用量统计信息

**任务历史记录：**
- 任务元数据指明 YOLO 模式是否处于活动状态
- 完整的操作日志显示自动批准情况
- 支持事后审查和分析

**审计日志：**
- 标准日志记录会捕获所有自动决策
- 工具执行及其时间戳会被记录
- 为受监管环境提供合规轨迹

## 按组织规模划分的推荐策略

### 小型团队（5-20 名开发者）
- **默认：** 禁用
- **例外：** 允许用于个人沙盒环境
- **监控：** 基本遥测已足够

### 中型组织（20-100 名开发者）
- **默认：** 禁用
- **例外：** 仅允许用于指定的开发/测试环境
- **监控：** 必须进行遥测并定期进行审计审查

### 大型企业（100+ 名开发者）
- **默认：** 严格禁用
- **例外：** 每个用例均需获得安全批准
- **监控：** 全面遥测 + 实时警报 + 合规报告

## 技术实现

### 配置管理

**通过远程配置进行集中控制：**

```json
{
  "yoloModeAllowed": false,
  // Other policies...
}
```

此设置：
- 立即应用于所有已连接的客户端
- 无法被单个用户覆盖
- 在 Cline 重启后仍然保留
- 在所有团队成员间同步

### 策略执行

执行机制：
1. 用户通过您的企业配置服务器进行身份验证
2. 下载并应用远程配置
3. 本地 UI 遵循企业策略设置
4. 如果策略禁止，YOLO 模式开关将被禁用
5. 用户会看到一条说明企业限制的消息

## 合规注意事项

对于受监管行业的组织：

**SOC 2 合规：**
- YOLO 模式可能与变更管理控制冲突
- 在安全策略中记录允许/禁止该模式的决定
- 如果允许使用 YOLO 模式，请实施补偿性控制

**GDPR/数据保护：**
- 自动化操作仍必须遵守数据处理策略
- 确保 YOLO 模式不会绕过数据保护措施
- 保留自动化数据处理的审计轨迹

**特定行业：**
- 金融服务：通常与监管要求不兼容
- 医疗保健：可能违反 HIPAA 审计轨迹要求
- 政府：通常与批准工作流要求冲突
