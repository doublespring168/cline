检查点让你可以撤销代码更改，而不会丢失对话。每当 Cline 修改文件或运行命令时，它都会保存项目文件的快照。你可以恢复到任意检查点，在还原代码的同时保留已经建立的上下文。

这改变了你与 Cline 协作的方式。你不必在批准前仔细审查每一项更改，而是可以让 Cline 快速推进，并在出现问题时回滚。犯错的成本几乎降为零。

<Tip>
检查点默认启用。如果需要将其关闭，请参阅[启用或禁用检查点](#%E5%90%AF%E7%94%A8%E6%88%96%E7%A6%81%E7%94%A8%E6%A3%80%E6%9F%A5%E7%82%B9)。
</Tip>

## 工作原理

Cline 会维护一个独立于项目实际 Git 历史记录的影子 Git 仓库。每次使用工具（编辑文件、运行命令等）后，Cline 都会将文件的当前状态提交到这个影子仓库。你的主 Git 仓库不会受到影响。

这意味着：

- 你的 Git 历史记录保持整洁并由你掌控
- 检查点会捕获所有内容，包括未被 Git 跟踪的文件
- 你可以恢复到任务中的任意时间点，而不会影响你已经创建的提交
- 检查点会跨编辑器会话保留

每个检查点都会捕获该时刻完整的文件状态。如果 Cline 依次编辑了三个文件，你会得到三个检查点，并且可以分别恢复到其中任意一个。

## 启用或禁用检查点

检查点默认启用。要切换此功能：

1. 打开 Cline 设置（Cline 侧边栏中的齿轮图标）
2. 滚动到“功能设置”部分
3. 切换“启用检查点”

<Note>
对于非常大的仓库，检查点可能会占用大量存储空间，并且由于每次使用工具后都要提交文件快照，可能会拖慢 Cline。如果你发现性能问题，请考虑将其禁用。
</Note>

## 查看和比较更改

每次使用工具后，对话中都会出现一个检查点指示器。查找标有“检查点”的书签图标，它通过虚线连接到**比较**和**恢复**按钮。

点击**比较**可打开差异视图，准确显示该检查点发生的更改。该视图会在编辑器的差异查看器中打开，让你看到所有受影响文件中的新增、删除和修改。

当 Cline 做出更改，而你想在决定是否保留这些更改前先了解它们时，这会很有用。你可以审查差异，然后选择继续或恢复以撤销更改。

## 恢复检查点

点击任意步骤旁的**恢复**，打开恢复菜单。你有三个选项：

| 选项 | 作用 | 使用时机 |
|--------|--------------|----------------|
| **恢复文件** | 将项目文件还原为此检查点的快照 | 撤销代码更改，同时保留对话 |
| **仅恢复任务** | 删除此时间点之后的消息，不影响文件 | 在保留当前代码的同时尝试不同的提示词 |
| **恢复文件和任务** | 还原文件并删除此时间点之后的消息 | 从已知的良好状态彻底重新开始 |

正确的选择取决于出了什么问题：

- 如果对话富有成效，但代码更改破坏了某些内容，请使用**恢复文件**。Cline 会保留你讨论过的所有上下文，并可以尝试不同的实现方式。

- 如果 Cline 的代码更改很好，但对话偏离了方向，请使用**仅恢复任务**。你可以保留文件，并以不同方式引导对话。

- 如果你想从干净状态重新开始，请使用**恢复文件和任务**。这会将文件和对话都重置到该检查点。

## 何时使用检查点

| 场景 | 建议操作 |
|----------|-------------------|
| Cline 重构代码后破坏了某些内容 | 恢复文件，并要求采用不同方案 |
| 尝试多种解决方案 | 比较每个检查点，并恢复到最佳方案 |
| Cline 误解了你的意图 | 恢复文件和任务，并重新表述请求 |
| 想尝试不同的提示词 | 仅恢复任务，保留文件，然后重新提交 |
| 提交到 Git 前审查更改 | 使用比较进行检查，然后手动提交 |
| 测试有风险的更改 | 让 Cline 继续，如果失败则恢复 |

## 与自动批准配合使用

检查点让[自动批准](/features/auto-approve)变得切实可用。没有检查点时，自动批准让人感觉有风险，因为 Cline 可能在你注意到问题之前就做出许多更改。有了检查点，你可以让 Cline 自主工作，并在需要时回滚。

典型工作流：

1. 为文件编辑和命令启用自动批准
2. 让 Cline 快速完成你的任务
3. 审查最终结果
4. 如果有问题，恢复到最后一个良好的检查点
5. 向 Cline 提供更具体的指导

这种方法比逐项审查每个更改更快，而检查点则提供了安全保障。

## 检查点与消息编辑

消息编辑功能与检查点相集成。当你编辑之前的消息并选择“全部恢复”时，Cline 会先将文件恢复到该时间点的检查点，然后重新提交你编辑后的消息。

这样，你可以通过一次操作修正措辞不当的提示词，并撤销由其产生的所有更改。
