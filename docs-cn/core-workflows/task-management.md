与 Cline 的每次交互都在任务中进行。任务是独立的工作会话，会记录你的完整对话、代码更改、命令执行和决策。

## 什么是任务？

当你向 Cline 提交提示词时，任务便开始了。你的提示词定义目标，Cline 通过对话、代码更改和工具使用来朝着目标推进。初始提示词的质量会直接影响 Cline 的表现——清晰、具体的提示词会带来更好的结果。

每个任务：

- 从你的提示词开始，并通过对话构建上下文
- 拥有唯一标识符和专用存储目录
- 包含完整的对话历史记录
- 跟踪 token 使用量、API 成本和执行时间
- 可以中断，并跨会话恢复
- 通过基于 Git 的快照为文件更改创建[检查点](/core-workflows/checkpoints)

<Tip>
想从 Cline 获得更好的结果？请在我们的[提示词模块](https://cline.bot/learn)中学习如何编写有效的提示词。
</Tip>

## 确定任务范围

每个任务都带有自己的上下文：对话历史记录、已经做出的决策，以及会话过程中形成的理解。你如何确定任务范围，会直接影响 Cline 能为你提供多好的帮助。

可以这样理解：**一个任务 = 一个目标**。“实现用户身份验证”是一个任务。“修复一个不相关的 CSS 错误”则是另一个任务，即使你是在处理身份验证时注意到它的。

聚焦的任务会带来更好的结果。当一个任务试图涵盖太多互不相关的目标时，上下文会变得杂乱，响应的相关性也会降低。

<Note>
如果不确定，宁可选择重新开始。你随时可以在任务历史记录中找到以前的会话。
</Note>

### 上下文窗口

每个 AI 模型都有一个上下文窗口——即一次可以处理的信息量上限。可以把它看作 Cline 针对当前任务的工作记忆。

随着工作的进行，上下文窗口会被以下内容逐渐填满：
- 你的提示词和 Cline 的响应
- Cline 读取或编辑的文件内容
- 命令输出和工具结果
- 指导 Cline 行为的系统指令（包括 [Cline 规则](/customization/cline-rules)）

当上下文窗口接近上限时，Cline 会自动压缩对话中较早的部分以腾出空间。这意味着非常长的任务可能会丢失一些早期细节，不过 Cline 会保留最重要的上下文。

这正是确定任务范围至关重要的原因：聚焦的任务会将相关信息保留在上下文窗口中。范围蔓延的任务会用噪声填满窗口，把有用的上下文挤出去。

如果即使是简单的提示词，初始上下文看起来也很高，请添加 [`.clineignore`](/customization/clineignore) 文件，以排除依赖项、构建产物以及 Cline 不需要的其他文件。这可以显著减少你的基准 token 使用量。

<Tip>
对于长时间运行的任务，请启用[自动压缩](/features/auto-compact)，在工作过程中智能管理上下文。
</Tip>

### 新任务与继续任务

一开始，判断何时应该重新开始、何时应该继续可能并不清晰。随着你更多地使用 Cline，你会逐渐形成直觉。可以将此表作为起点：

| 场景 | 操作 | 原因 |
|----------|--------|-----|
| 切换到不同功能 | **新任务** | 上下文干净，响应更聚焦 |
| 基于 Cline 刚完成的工作继续构建 | **继续** | 保留共同理解 |
| Cline 不断偏离方向 | **新任务** | 与上下文对抗会浪费时间 |
| 在相同文件上反复完善 | **继续** | 对话历史记录会有帮助 |
| 说明要忽略的内容 | **新任务** | 杂乱的上下文会损害质量 |
| 完善 Cline 上一次的输出 | **继续** | 保留推进势头和已做决策 |

要开始新任务，请点击 Cline 侧边栏中的 **+** 按钮，或使用 `/newtask` 命令。你的文件更改会通过[检查点](/core-workflows/checkpoints)保留，并且可以随时从历史记录中引用以前的任务。

## 了解任务成本

每个基于云的 AI 模型都会根据 token 使用量收费，token 是模型处理文本的单位。Cline 会自动跟踪这些成本并将其显示在任务标题中，便于你在工作时监控支出。

### 成本如何计算

与 Cline 交互时，模型会处理：

- **输入 token**：你的提示词、文件内容、对话历史记录和系统指令
- **输出 token**：模型的响应、代码建议和工具调用

云提供商按每百万 token 收费，输出 token 的费用通常高于输入 token。一些提供商还支持**提示词缓存**，当相同上下文（例如你的 cline 规则或大型文件）出现在多个请求中时，可以降低成本。Cline 会在可用时自动跟踪缓存节省的费用。

任务标题中显示的预估成本会在每次 API 请求后更新。此估算使用你所选提供商的定价信息，并且根据提供商的舍入方式或用量计费方式，可能与你的最终账单略有不同。

### 何时付费

使用 Anthropic、OpenAI、OpenRouter 或 Google 等云提供商时，你需要为 AI 使用付费。成本差异很大：

| 提供商类型 | 计费模式 |
|--------------|---------------|
| **Cline 提供商** | 使用你购买的额度按使用量付费 |
| **直接 API 密钥** | 由你的提供商（Anthropic、OpenAI 等）计费 |
| **OpenRouter/Requesty** | 跨多个模型的聚合计费 |
| **本地模型** | 免费（硬件由你提供） |

如果你使用自己的 API 密钥，请查看提供商的定价页面以获取当前费率。价格会频繁变化，且因模型而异。

### 免费选项

还没准备好付费？Cline 提供多种免费途径：

- **免费模型**：使用 Cline 提供商时，在模型选择器中搜索“free”。这些模型会显示 **FREE** 标签，非常适合学习和实验。
- **免费额度**：一些提供商会在你使用自己的 API 密钥时提供有限的免费用量。
- **本地模型**：在你自己的硬件上运行模型，每次请求的成本为零。

### 自托管模型

在本地运行模型意味着永远不产生 API 成本。你唯一的开支是运行模型所需的硬件。

要有效运行本地模型，你需要：

- 入门级模型（4-bit 量化）至少需要 **32GB RAM**
- 要获得更好的质量（8-bit 量化），需要 **64GB RAM**
- 要获得可与云端媲美的性能，需要 **128GB+ RAM**

代价是速度。典型硬件上的本地模型每秒运行 5-20 个 token，而云 API 每秒可运行数百个 token。本地模型还需要更多设置和配置。

<Tip>
如果你拥有相应硬件，本地模型可以提供完全隐私的无限实验。请参阅[在本地运行模型](/running-models-locally/overview)开始使用。
</Tip>

对于大多数用户，从免费云模型开始，并根据需要转向付费选项，可以在成本、速度和能力之间取得最佳平衡。请查看[选择模型](/getting-started/authorizing-with-cline)，了解如何为你的工作流选择合适的选项。


## 任务历史记录

你处理的每个任务都会自动保存到本地计算机。你可以重新查看过去的对话、恢复中断的工作，或参考早期会话中的成功方案。

### 查找历史记录

点击 Cline 侧边栏中的**历史记录**按钮（右上角的时钟图标），打开历史记录视图。你会看到过去的所有任务，其中包含初始提示词、时间戳和 token 使用量。每个任务卡片都可以展开，显示对话预览。

### 搜索任务

使用历史记录视图顶部的搜索栏查找特定任务。模糊搜索会检索所有内容：你的提示词、Cline 的响应、代码片段和文件名。

结果排序方式：
- **最新/最早**，按时间顺序浏览
- **最昂贵/最多 token**，查找资源消耗较大的任务
- **最相关**，用于搜索特定内容时
- **收藏**，仅显示已加星标的任务

<Tip>
有策略地使用收藏功能。为那些代表成功模式、优秀提示词或你以后可能想要参考的复杂工作的任务加星标。已收藏的任务会受到保护，不会被删除。
</Tip>

## 恢复任务

Cline 可以在保留完整上下文的情况下恢复中断的任务：

1. 从历史记录中打开任务
2. Cline 加载完整对话
3. 根据[检查点](/core-workflows/checkpoints)检查文件状态
4. 任务会在知晓中断情况的前提下继续
5. 如有需要，提供额外上下文

这可以跨会话工作。即使你关闭编辑器并在几天后返回，Cline 也可以从中断处继续。
