规划与执行模式将思考与动手操作分开。规划模式让你可以在不更改文件的情况下探索和制定策略。执行模式则按照你的计划付诸实施。

<Tip>
	**刚开始使用规划与执行模式？** 观看[规划与执行深度解析](https://youtu.be/b7o6URFPp64)，了解它的实际运行方式。
</Tip>

## 规划模式

在规划模式中，你和 Cline 会弄清楚要构建什么以及如何构建。在此模式下，Cline 可以读取你的代码库、运行搜索并讨论策略，但不能修改任何文件或执行命令。

这种限制是有意为之。它让对话专注于理解和规划，而不会受到实现细节的干扰。你可以自由探索、提出问题，并在决定进行更改之前反复完善方案。

使用规划模式来：

- 在进行更改前探索不熟悉的代码库
- 讨论架构决策和权衡
- 提前识别边缘情况和潜在问题
- 制定清晰的实施策略
- 审查代码并理解复杂工作流

## 执行模式

制定计划后，切换到执行模式。Cline 会保留规划会话中的完整上下文，此时可以修改文件、运行命令并执行你的策略。

切换模式时，对话历史记录会一并保留。Cline 会记住你在规划模式中讨论的所有内容，因此无需重复说明。这使得模式转换无缝顺畅。

<Note>
	虽然你可以直接从执行模式开始，但强烈建议先进行规划。规划阶段会有意构建 Cline 有效实施更改所需的上下文。缺少这一阶段，Cline 可能无法获得做出正确决策所需的理解。
</Note>

## 典型工作流

1. 从规划模式开始，描述你想要构建的内容
2. 让 Cline 探索相关文件并理解代码库
3. 讨论方案，同时考虑边缘情况和潜在问题
4. 对计划有信心后，切换到执行模式
5. Cline 根据你的规划会话实施解决方案

对于复杂项目，你可能需要多次在两种模式之间切换。遇到意料之外的复杂情况或需要重新思考方案时，返回规划模式，然后再切换回执行模式继续实施。

## 每种模式的使用时机

| 场景 | 建议模式 |
|----------|-----------------|
| 开始开发方案并不明显的新功能 | 规划 |
| 调试难以处理且不确定问题所在的故障 | 规划 |
| 做出影响多个文件的架构决策 | 规划 |
| 在修改复杂工作流前先理解它们 | 规划 |
| 代码审查和安全分析 | 规划 |
| 学习新的代码库 | 规划 |
| 实施已经规划好的解决方案 | 执行 |
| 按清晰方案进行常规更改 | 执行 |
| 遵循代码库中已经确立的模式 | 执行 |
| 运行测试并进行调整 | 执行 |
| 解决方案显而易见的快速修复 | 执行 |

## 为每种模式使用不同模型

你可以为规划和执行模式分别配置模型。如果你希望使用推理能力更强的模型进行规划，并使用速度更快的模型进行实施，这会很有用。

要启用此功能：

1. 打开 Cline 设置
2. 启用“为规划和执行使用不同模型”
3. 为每种模式选择你偏好的模型

启用后，在规划和执行模式之间切换时，会自动切换到为该模式配置的模型。切换回来时，你的模型选择会得到保留。

**配置示例：**

| 用例 | 规划模式 | 执行模式 |
|----------|-----------|----------|
| 成本优化 | GLM 4.6 | Grok Code Fast |
| 最高质量 | Claude Opus | Claude Sonnet |
| 注重速度 | Gemini 3 Flash | Cerebras |

## 使用 `/deep-planning`

对于需要全面分析的复杂任务，请使用 `/deep-planning` 斜杠命令。这会触发一个扩展规划会话，在其中 Cline 会：

1. 系统地探索代码库
2. 识别所有受影响的文件和依赖项
3. 创建详细的实施计划
4. 在继续之前提出澄清问题

深度规划提示词针对每个模型系列进行了优化，因此会适应你所用模型的优势。有关更多详细信息，请参阅 [/deep-planning](/core-workflows/using-commands#%2Fdeep-planning)。

## 根据任务规模选择正确方案

### 小型任务：仅使用执行模式

对于拼写错误、简单错误修复或遵循既有模式等快速修复，请直接从执行模式开始。当解决方案显而易见时，规划只会增加额外开销。

**示例：** 修复拼写错误、添加缺失的导入、更新配置值、重命名变量。

### 中型任务：规划 → 执行

对于大多数开发工作，先从规划模式开始以了解范围和方案，然后切换到执行模式进行实施。对于涉及少量文件且具有一定复杂性的功能，这是最佳选择。

**示例：** 添加新的 API 端点、实现 UI 组件、修复需要调查的错误、重构单个模块。

### 大型任务：使用 `/deep-planning`

对于跨越多个文件、需要架构决策或需要多个会话才能完成的复杂功能，请使用 `/deep-planning` 斜杠命令。这会创建详细的实施计划，供 Cline 在整个工作过程中参考。

**示例：** 添加跨前端和后端的新功能、对整个代码库进行重大重构、实现新系统或集成、多步骤迁移。

## 提示

- 让 Cline 编写一个总结计划的 Markdown 文件，供将来参考
- 在规划期间使用[文件提及](/core-workflows/working-with-files)将 Cline 指向相关文件
- 遇到意料之外的复杂情况时，切换回规划模式，而不是强行推进
- 在执行模式前启用[检查点](/core-workflows/checkpoints)，以便在需要时回滚
- 对于大型任务，在规划期间让 Cline 创建一个待办事项列表，以便在执行模式中跟踪
