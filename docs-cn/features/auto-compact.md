当你的对话接近模型的上下文窗口限制时，Cline 会自动对其进行总结，以释放空间并继续工作。

</Frame>

## 工作原理

Cline 会在对话期间监控 token 使用量。当你接近限制时，它会：

1. 创建一份全面的总结，涵盖已经发生的一切
2. 保留所有技术细节、代码更改和决策
3. 用总结替换对话历史记录
4. 从中断的位置准确地继续工作

发生这种情况时，你会看到一次总结工具调用，其费用会像其他任何 API 调用一样显示。

## 为什么这很重要

此前，Cline 在达到上下文限制时会截断较早的消息，从而丢失重要上下文。

现在有了总结功能：
- 所有技术决策和代码模式都会得到保留
- 文件更改和项目上下文保持不变
- Cline 会记得它做过的一切
- 你可以不受中断地处理规模大得多的项目

<Tip>
自动压缩特别适合长时间运行的任务。结构化任务列表有助于在多次总结之间维持进度，使 Cline 能够跨越多个上下文窗口保持正轨。
</Tip>

## 费用考量

总结功能会利用对话中已有的提示缓存，因此费用与其他任何工具调用大致相同。

由于大多数输入 token 已经缓存，你主要为总结生成（输出 token）付费，因此成本效益很高。

<Note>
使用其他模型时，即使启用了自动压缩，Cline 也会回退到基于标准规则的上下文截断。
</Note>

## 恢复上下文

你可以使用[检查点](/core-workflows/checkpoints)恢复总结发生前的任务状态。你永远不会真正丢失上下文，因为你随时都可以回滚。

编辑总结工具调用之前的消息也有类似效果，会将对话恢复到该时间点。
