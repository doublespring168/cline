自动批准让你决定 Cline 无需每次提示即可执行哪些操作。它能让你在日常工作中免受批准弹窗打扰，同时仍可严格控制高风险操作。

如果你发现自己总是在为相同的安全操作反复点击批准，自动批准可以解决这个问题。

## 工作原理

自动批准会针对每次工具调用进行评估。当 Cline 即将读取文件、编辑文件、运行命令或使用浏览器时，它会检查该类别对应的自动批准设置。

有几个细节很重要：

- **工作区与工作区外部**：“读取所有文件”和“编辑所有文件”只能扩展基础开关的权限。如果基础开关处于关闭状态，“所有文件”选项不会起任何作用。
- **终端命令**：Cline 将命令分为安全命令和需要批准的命令。“执行安全命令”涵盖安全命令。“执行所有命令”则将范围扩展到被标记为需要批准的命令。
- **通知**：如果启用，当需要批准时，以及自动批准的终端命令已运行 30 秒时，Cline 会发送操作系统级通知。

## 权限

| 设置 | 允许的操作 |
|---------|----------------|
| 读取项目文件 | 读取文件、列出文件、在工作区中搜索 |
| 读取所有文件 | 读取工作区外部的文件（需要基础开关） |
| 编辑项目文件 | 在工作区中创建和编辑文件 |
| 编辑所有文件 | 编辑工作区外部的文件（需要基础开关） |
| 执行安全命令 | 运行标记为安全的终端命令 |
| 执行所有命令 | 运行需要批准的命令（需要基础开关） |
| 使用浏览器 | 用于网页获取和搜索的浏览器工具 |
| 使用 MCP 服务器 | MCP 工具和资源 |
| 启用通知 | 通知你长时间运行的命令 |

<Warning>
“读取所有文件”和“编辑所有文件”仅在对应的基础开关启用时才有意义。它们会将访问范围扩展到工作区之外。
</Warning>

## 安全命令与需要批准的命令

Cline 不使用固定的允许列表。模型会根据命令和参数，使用 `requires_approval` 标志标记每条命令。以下只是示例，并非保证。

**通常被视为安全：**
- `npm run build`、`npm test` - 构建/测试输出
- `git status`、`ls -la`、`cat package.json` - 只读命令

**通常需要批准：**
- `npm install <pkg>` - 修改依赖项
- `rm -rf <path>` - 删除文件
- `mv <a> <b>` - 移动文件（可能会覆盖）
- `sed -i ...` - 原地编辑文件

## 建议

一套不错的默认设置：
- 启用**读取项目文件**
- 在没有具体原因之前，保持编辑、命令、浏览器和 MCP 关闭

如果启用编辑，请使用[检查点](/core-workflows/checkpoints)，以便快速回滚。

## YOLO 模式

YOLO 模式是火力全开的自动批准。勾选此框后，Cline 会自动批准一切：文件更改、终端命令、浏览器操作、MCP 工具和模式转换。

<Note>
**警告：这很危险。** YOLO 模式会禁用所有安全检查。Cline 会执行它所决定的任何操作，而不会请求许可。
</Note>

### 会自动批准哪些操作

启用 YOLO 模式后：
- 系统中任何位置的所有文件操作
- 所有终端命令，包括可能具有破坏性的命令
- 浏览器操作
- MCP 服务器工具
- 模式转换（从 Plan 切换到 Act）

### 何时使用 YOLO 模式

**快速原型开发**，适用于你希望零阻力且不在意潜在错误的情况。非常适合一次性实验。

**可信、重复的任务**，适用于你已经验证过 Cline 的处理方式，并希望消除批准开销的情况。

**演示用途**，适用于你希望不受打断地展示 Cline 能力的情况。

### 可能出现什么问题

Cline 可能会：
- 在没有警告的情况下删除重要文件
- 执行修改系统设置的命令
- 向外部服务发出网络请求
- 覆盖配置文件
- 安装或卸载软件包
- 将更改提交并推送到版本控制系统

### YOLO 模式最佳实践

- **从隔离环境开始。** 首先使用一次性项目或沙盒环境。
- **提出具体的请求。** 模糊指令 + 无限制权限 = 不可预测的结果。
- **监控输出。** Cline 仍会显示它正在做什么。留意终端和文件更改。
- **随时准备好版本控制。** Git 会成为你的安全网。

### 启用 YOLO 模式

前往 Cline 设置，进入“功能”，然后勾选“YOLO 模式”。不会出现确认对话框。启用后，Cline 会立即自动批准所有操作。取消勾选即可禁用。
