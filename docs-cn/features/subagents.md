子智能体让 Cline 可以生成并行运行的专注型研究智能体。每个子智能体都有自己的提示词和上下文窗口，独立探索代码库，并向主智能体返回详细报告。这样既能保持主智能体上下文整洁，又能快速收集广泛的信息。

<Tip>
  子智能体是一项实验性功能。其行为可能会在未来版本中发生变化。
</Tip>

## 工作原理

当 Cline 使用 `use_subagents` 工具时，它会同时启动多个独立智能体。每个智能体：

- 都会获得描述调查内容的专属提示词
- 使用独立的上下文窗口和 token 预算运行
- 可以读取文件、搜索代码、列出目录、运行只读命令以及使用技能
- 无法编辑文件、使用浏览器、访问 MCP 服务器或生成嵌套子智能体
- 返回聚焦于最相关文件路径的结果，供主智能体接下来读取

子智能体的费用（token 和 API 支出）会按子智能体分别跟踪，并计入任务总费用。子智能体运行时，你可以在聊天 UI 中查看每个子智能体的统计信息（工具调用、token、费用）。

## 启用子智能体

子智能体默认启用。Cline 会自行判断并行研究是否值得其额外开销——你无需选择启用，也不必在提示词中专门说明。要关闭子智能体，请在 Settings → Features → Agent 中禁用 `use_subagents` 工具。

此设置适用于所有编辑器（VS Code、JetBrains、CLI）。

## 使用子智能体

启用子智能体后，当任务适合并行探索时，Cline 会自行使用它们。你也可以在提示词中要求并行研究，明确推动它这么做。

示例提示词：

- “使用子智能体探索身份验证的工作方式，以及数据库模型定义在哪里”
- “启动子智能体，分别调查 API 路由、测试设置和部署配置”
- “我刚接触这个代码库。使用子智能体梳理主要入口点、路由层和数据访问模式”

每个子智能体提示词都应描述一个聚焦的研究问题。Cline 会并行运行它们并综合结果。
你也可以只运行一个子智能体，适用于任务规模较小、并行发现会带来不必要开销的情况。

## 自动批准行为

子智能体遵循**读取项目文件**自动批准权限。如果你在[自动批准](/features/auto-approve)中启用了“读取项目文件”，子智能体启动将会被自动批准。

如果自动批准处于关闭状态，Cline 会在启动子智能体之前请求你的批准，并向你展示它计划发送的提示词。

## 子智能体可以做什么

子智能体是只读研究智能体。以下是它们可以访问的工具：

| 工具 | 用途 |
|------|---------|
| `read_file` | 读取文件内容 |
| `list_files` | 列出目录内容 |
| `search_files` | 使用正则表达式跨文件搜索 |
| `list_code_definition_names` | 列出顶层类、函数和方法 |
| `execute_command` | 运行只读命令（`ls`、`grep`、`git log`、`git diff` 等） |
| `use_skill` | 加载并激活技能 |

子智能体无法写入文件、应用补丁、使用浏览器、访问 MCP 服务器或执行网页搜索。它们也无法生成自己的子智能体。

<Note>
  子智能体运行的命令在后台执行，并且仅限只读操作。子智能体不会运行会修改文件或系统状态的命令。
  子智能体还可以利用命令管道和过滤器，在读取文件之前快速缩小输出范围，例如 `rg ... | sort | uniq`。
</Note>

## 何时使用子智能体

当你需要同时从代码库的多个区域获取广泛上下文时，子智能体最为适用：

- **熟悉陌生项目**：让子智能体并行梳理架构、关键入口点和数据流。
- **调查横切关注点**：让不同的子智能体同时跟踪身份验证、日志记录和错误处理。
- **编辑前研究**：在进行更改之前，使用子智能体从相关文件中收集上下文，使主智能体可以在不耗尽上下文窗口的情况下做出明智的编辑。
- **大型代码库**：当按顺序读取大量文件会占用过多主智能体上下文时，子智能体让你可以进行广泛探索，而无需做出这种取舍。

对于你已经知道要查看哪些文件的小型聚焦任务，子智能体会增加不必要的开销。直接询问 Cline 即可。
