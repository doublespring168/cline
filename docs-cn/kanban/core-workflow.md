title: "核心工作流"
description: "使用 Cline Kanban 的端到端工作流：创建任务、运行智能体、审查变更并交付"
---

本指南将从头到尾介绍典型的 Kanban 工作流。

## 1. 创建任务

有两种方式可将任务添加到看板：

- **手动** — 点击添加按钮并编写任务描述
- **通过侧边栏聊天** — 打开侧边栏聊天，让智能体将一项工作拆分为多个任务。智能体可以创建卡片、将它们关联起来，并直接在看板上开始工作。

看板上的每张卡片都代表一个需要智能体完成的独立工作单元。

## 2. 关联任务

将卡片关联起来以创建依赖链：

- 对卡片执行 **⌘ + 点击** (Mac) / **Ctrl + 点击** (Windows/Linux)，将其关联到另一项任务
- 当一张已关联的卡片完成并被移至回收站后，下一个关联任务会**自动开始**

与自动提交结合使用时，这可以实现完全自主的任务链，其中一项任务的输出会成为下一项任务的输入，无需人工干预。

## 3. 开始任务

点击卡片上的**播放按钮**即可启动任务。随后会发生以下事情：

1. Kanban 为该任务创建一个**临时 git worktree** — 这是仓库的隔离副本，智能体可以在其中进行更改，而不会影响主工作目录或其他任务
2. `node_modules` 等被 git 忽略的文件会从主仓库**符号链接**到 worktree 中，从而避免为每项任务进行耗时的重复安装
3. 智能体开始在该 worktree 内自己的终端中工作
4. 卡片会显示智能体的**最新消息或工具调用**，以便你从看板监控进度

多个任务并行运行，每个任务都有自己的 worktree，因此智能体之间绝不会产生合并冲突。

<Warning>
符号链接非常适合智能体无需修改的被 git 忽略文件（如 `node_modules`）。如果你的工作流要求智能体修改被 git 忽略的文件，请注意，更改会影响符号链接的目标（即主仓库中的副本）。
</Warning>

## 4. 审查变更

点击卡片打开详情视图，其中显示：

- **智能体的 TUI** — 显示智能体对话和操作的完整文本界面
- 该 worktree 与基础分支相比的**所有变更 diff**

diff 查看器包含一个**检查点系统** — 你可以查看限定到特定消息范围的 diff，而不仅仅是完整的累积 diff。这让你能够更轻松地了解发生了哪些更改以及更改发生的时间。

### 行内评论

点击 diff 中的任意一行即可留下评论。评论会作为反馈发送回智能体，让你无需重写任务描述就能引导其工作。这对于“这里采用另一种方法”或“这个边界情况尚未处理”等纠正意见很有用。

## 5. 交付

对变更感到满意后，你有两个选择：

- **提交** — 将 worktree 变更合并为基础分支上的一个提交
- **打开 PR** — 创建一个新分支并打开 pull request

在这两种情况下，Kanban 都会向智能体发送动态提示以处理该操作。智能体会将 worktree 转换为适当的 git 操作，并且如果基础分支在 worktree 创建后发生了变化，还会**智能处理合并冲突**。

## 6. 清理

交付后，将卡片移至**回收站**，以清理临时 worktree 并释放磁盘空间。

<Tip>
如果以后需要恢复已移入回收站的卡片上的工作，Kanban 会为每项任务提供一个 **resume ID**。你可以使用它从上次停止的位置继续。
</Tip>

## 工作流总结

| 步骤 | 操作 | 会发生什么 |
|------|--------|-------------|
| 创建 | 添加卡片或使用侧边栏聊天 | 任务卡片出现在看板上 |
| 关联 | ⌘ + 点击以连接卡片 | 建立依赖链 |
| 开始 | 点击卡片上的播放按钮 | 创建临时 worktree，智能体开始工作 |
| 监控 | 在看板上查看卡片状态 | 卡片上显示智能体的最新消息/工具调用 |
| 审查 | 点击卡片查看 diff | 包含检查点和行内评论功能的完整 diff |
| 交付 | 点击提交或打开 PR | 智能体负责合并到基础分支或创建 PR |
| 清理 | 移至回收站 | 移除 worktree，并保存 resume ID |
